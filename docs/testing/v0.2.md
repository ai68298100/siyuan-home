## 8. 集成测试（端点实测已完成，UI 清单待真机走查）

单元测试（`tests/core/`）全部使用 mock transport，不依赖真实内核。以下是需要真机实例才能验证的集成测试清单：

**自动化脚本（2026-10-04 第七十六波建，第七十九波实测跑通）**：`scripts/e2e-endpoints.sh`——后台验证 render 分页、PK 分页、asset 上传，自动建库造数清理。**工作区鉴权门**：实例被多插件会话共用并切换工作区，token 只对本工作区有效——脚本稳定判定用带鉴权探测（lsNotebooks），正确拒绝外来工作区（version 免鉴权不可作判据）；本工作区窗口未出现时脚本安全退出。

### 2026-10-04 端点实测结论（第七十九波，真机 150 行库）

| # | 结论 | 证据 |
|---|---|---|
| E1 | **renderAttributeView 默认分页成立**：`rowCount`=全量计数（150），`rows` 只返回视图 pageSize（默认 50）行 | 150 行库原始 curl：`rowCount:150 rows.length:50 pageSize:50` |
| E2 | **getAttributeViewPrimaryKeyValues 分页语义**：显式 `pageSize` 为封顶上限（100→恰 100，200→全量 150），`page` 翻页无重叠；**250 行库复测：pk1=200（恰一页）、pk2=50（<pageSize 终止）、∩=0——插件 D01 循环"返回数<pageSize 即止"的终止条件在边界上成立（IT-03 ✅ 81 波）** | ps=100→100 行；ps=200→150 行；250 行库 page1∩page2=0 |
| E3 | **SQL API 表清单不含 notebooks**：可用表=assets/attributes/blocks(+FTS)/refs/spans/stat；笔记本 id 只能走 lsNotebooks | `sqlite_master` 查询实测 |
| E4 | **加列端点实名 `addAttributeViewKey`**（`addAttributeViewColumn` 不存在）；**`keyID` 必须自造**（YYYYMMDDHHMMSS-xxxxxx 形态；留空会建出 id 为空串的不可用列——81 波写路径探针修正） | 空串列实测复现；显式 id 列正常 |
| E5 | **removeDoc(path) 恒报 block not found**（open 笔记本后依旧）；**`removeDocByID(id)` 可用**（code 0，经索引延迟后生效） | 两种端点对照实测；包装器 HIGH 安全门要求 `-y` |
| E6 | **asset upload 可用**：multipart `file[]=...` → code 0 + succMap（assets/lvh-upload-test-<ts>.txt） | 脚本实测 |
| E7 | **detached 行批量建行可用**：addAttributeViewBlocks 5×30 全部生效（150 行入库）；**响应 `data:null` 不带任何行 ID**——插件 D02 的"render 前后 diff 确认行 ID"策略是必要的（82 波探针证实） | rowCount 复核 + 响应体捕获 |
| E8 | **sy 包装器大响应静默截断**（>~64KB JSON 中段被砍）→ render/PK 等大响应用原始 curl + 文件落地解析；MSYS 禁转换下 curl 文件参数需 cygpath 转 Windows 路径 | 三轮调试定位 |
| E9 | createDocWithMd 返回值为 JSON 字符串字面量（带引号）；insertBlock 响应内含新建 av 块 data-node-id（无需等 SQL 索引即可拿到块 ID） | 脚本注释 |
| E10 | **写/删行行为面证实（82 波探针）**：`batchSetAttributeViewBlockAttrs{avID, values:[{keyID, itemID, value}]}` 写 text 单元格 → render 读回一致（itemID=render row.id，再次验证 D02 的 ID 空间）；`removeAttributeViewBlocks{avID, srcIDs:[rowId]}` 删行 → rowCount 即减（2→1） | 写读回 + 删行复测 |
| E11 | **删行只认 render row.id 空间（182 波活体套件首跑实证）**：`removeAttributeViewBlocks` 传入 PK values id（`getAttributeViewPrimaryKeyValues` 返回的行 ID）**静默无效**（不报错、行数不变）；D02"两套 ID 空间"论断延伸到删除路径——>50 行（render 单页上限）台账的批量删除只能按 render 分页逐页删 | 60 批量行 PK id 批删 → rowCount 62 不变；render 分页逐页删 → 归零 |
| E12 | **insertBlock 响应同步提取新块 ID 已进插件（182 波）**：忙实例上"固定等待 400ms + SQL 索引回查"会落空（索引重建更慢）——`createAttributeView` 改为优先取 E9 的 `doOperations[].data` data-node-id，SQL 轮询仅作回退；活体套件建库 setup 因此从必败转绿 | 活体套件 setup 两态对照 |

对插件的影响：E1/E2 直接验证 D01（主键行 ID 全量逐页读取）为必要设计——不能依赖单次 render 拿全行；E4/E5 修正两处端点用法（插件内部用的是 fetchSyncPost 直名端点，不受包装器影响）；E11 约束一切删行调用方（rowIDs 必须来自 render 空间）。
