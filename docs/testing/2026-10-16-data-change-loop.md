# v0.5.23 数据变化重载循环回归

日期：2026-10-16。靶场为 `tmp/sy-ui3`、SiYuan 3.8.7、`127.0.0.1:14680`；使用真实 Chrome 的两个独立 browser context，共用同一隔离工作区。未操作日常工作区。

## 现象与原因

用户录像中欢迎提示反复出现，顶栏按钮消失重现，页面不断重建。0.5.22 双前端实验在十多秒内记录 A 端 17 个实例 / 16 次卸载、B 端 16 个实例 / 16 次卸载，持续写入 settings/runtime，浏览器 pageerror 仍为 0。

SiYuan 未检测到自定义 `onDataChanged` 时会重载整个插件。管家启动又建库保存设置、扫描保存运行态，使两个前端互相触发重载。仅检查 history 或 pageerror 无法覆盖此故障。

## 修复与门禁

- `onDataChanged` 只读摄入设置/运行态并原位刷新；不调用启动、建库、持久化扫描或启动消息。
- 接收与本地运行态动作共用写入串行边界，避免同步读取覆盖本地正在提交的备忘等动作。
- 无变化的设置与接收后未变更的运行态不重复写入；不完整/损坏的接收保留上次可用状态。
- 卸载前后有守卫，在途读取与排队通知不能重新激活 UI。

构建产物门禁 `pnpm verify:loader` 覆盖生命周期 override、重复 overwrite/sync、错误信封、损坏数据、本地保存竞态和卸载时序；旧产物缺少 override 时明确失败。仅在内存移除新锁后，竞态回归也能准确失败。

宿主门禁 `pnpm ui:data-change` 临时将隔离 fixture 设置为首次引导，检查三轮双向设置及运行态写入。接收端必须读到新值，不能回写；实例、按钮和面板节点保持同一对象，首次提示每端至多一次且后续不增长。测试关闭前端后逐字节恢复原有存储 fixture。

## 结果与边界

修复版三轮共六次主动写入后，两端均为 1 个实例、0 次卸载、0 次按钮/面板节点消失；每次变更接收端写入为 0。欢迎提示每端各一次，后续没有增长，pageerror 为 0。原有 `ui:history` 另外检查页签切换、刷新、历史栈稳定与唯一挂载。

这是隔离内核与 Chrome 前端证据；不替代真实 Android WebView、所有第三方主题/插件、多设备文件冲突和生产工作区验证。升级后需关闭旧浏览器前端并完整重启思源，让各前端都加载新代码。
