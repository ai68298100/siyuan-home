# 同类家庭生活管理产品调研（第二轮 · 2026-10-20）

> 调研目的：在 2026-10-19 首轮调研（Homechart / Cozi / Grocy / Wallos / Mealie / Notion Family OS）基础上，
> 扩展覆盖 2026 年新兴的自托管家管项目与「家庭 lifehub」品类，识别小驴管家尚未覆盖的真实缺口，
> 为下一阶段波次开发提供输入。
>
> 本轮样本：OpenFamily、Oikos/Yuvomi、Donetick、Monica、KitchenOwl、Quicken LifeHub、Everplans、
> AnnualVault、RemindMe、Warranty Keeper、Dalà、Homsy、OurFamily、智辰家纪事（国内小程序）。

---

## 一、样本与定位矩阵

| 产品 | 形态 | 核心定位 | 对小驴管家的启示 |
|---|---|---|---|
| **OpenFamily**（AGPL, 自托管） | Web/PWA | Cozi 自托管替代：清单/任务/日历/周计划/菜谱/餐单/预算 | **按过道分组的购物模式（aisle-by-aisle store mode）**；预算的**分类限额 + 超限告警**；邀请链接 + **访问请求 / 所有权转移** |
| **Oikos / Yuvomi**（MIT, 自托管） | Web/PWA, 20 模块 | 「多个订阅 → 一个家」：任务/日历/预算/餐单/健康/文档/家务/垃圾回收 | **垃圾回收日程（含"每月最后一个周五"式规则 + 市政 ICS 订阅）**；库存模块的**收据关联 + 服务日志 + 循环截止提醒**；**积分奖励 + 家长审核 + 零花钱账本**；**MCP 端点供 AI 代理** |
| **Donetick**（AGPL, Go） | Docker | 家务轮换与催办（Cozi 家务部分的专注替代） | **轮换（rotation）**：同一项活不在同一人身上连续出现；**nagging**：未完成持续催办直至完成 |
| **Monica**（AGPL） | Web | 个人关系管理：联系人/生日/提醒/日记 | 人物关系网与**往来历史时间轴**的呈现方式 |
| **KitchenOwl**（AGPL, Flutter） | Web+App | 家庭共享购物清单 + 菜谱 | **购物模式**的触屏快捷勾选与离线可用 |
| **Quicken LifeHub** | 商业云 | 家庭 lifehub：证件/保险/房产/医疗/法务/遗产档案 + 四类家庭角色 | **分级角色（Owner / Co-owner / Editor / Viewer，按文件夹授权）**；**"谁能看到、何时可见"（现在 / 身后）**；**所有权转移（Transfer of Ownership）**；Smart Add 拍照建档 |
| **Everplans / adeus / NeuVault** | 商业云 | 数字遗产与家庭档案托管 | 「身后交接」作为**独立于日常使用的模式**，而非单纯的权限位 |
| **AnnualVault** | 商业 | 年度服务与合规续期（60/30/7 天三段提醒） | **多段式提醒割点（60/30/7）**，而非单一提前量 |
| **RemindMe** | iOS | 纯日期跟踪（30/15 天提醒），不存文件 | 「只记日期不存证」的极简定位，说明**低承诺入口**的价值 |
| **Warranty Keeper / WarrantyVault** | 移动 | 保修期跟踪（7/15/30/60 天可选） | **用户可选提醒割点**，而非固定提前量 |
| **Dalà** | 商业 App | 分离/重组家庭：监护日历、共享重要医疗信息、凭码分享 | **邀请码 + 按角色调整可见范围**（祖父母/保姆只读，医疗信息对祖父母保密）；**监护日历（隔周轮换等模式）** |
| **Homsy** | 商业 App | 家务轮换 + 完成记录 + 最近加入膳食/预算 | **完成记录是平息"谁做了"争议的唯一证据** |
| **OurFamily** | 单次买断 App | 纯本地：成员/证件夹/提醒/联系人/资产/月度预算 | **证件夹的"存放位置"字段（家里保险箱 / 银行保险柜）**；一次性买断的定价模型 |
| **智辰家纪事**（国内小程序） | 微信小程序 | 三代家庭数字档案：儿童成长/中青年/长辈慢病 | **按家庭生命周期角色（小孩/中青年/长辈）组织档案**，而非按台账模块；**血压血糖趋势对比**；三级权限（户主/成员/访客） |

## 二、小驴管家已覆盖 vs 真实缺口

### 已覆盖（无需重复开发）

- 31 模块台账（成员/证件/合同/健康/购物/囤货/影音/旅行/宠物/育儿/教育/车辆…）+ 属性视图原生双向编辑
- 统一提醒中枢：多规则派生（oneoff / recurring / anniversary / after）、农历、静默时段、Webhook 外推
- 常用分析：订阅年化、支出趋势、用药供给、疫苗排期、宠物生理年龄、农业/社保退休、生活指数
- 导出通道：CSV / ICS / VCF / JSON / 诊断包 / 附件归档清单
- 访客只读模式、脱敏复制、附件离线归档

### 真实缺口（本轮新增识别）

| # | 缺口 | 来源印证 | 价值判断 | 实现成本 |
|---|---|---|---|---|
| **G1** | **家务/周期性任务的"责任轮换 + 完成留痕"** | Donetick / Homsy / OpenFamily | 高——家庭摩擦的第一来源就是"轮到谁"；完成后无记录则争议无法消解 | 中（chores 模块已存在，缺轮换状态与完成日志） |
| **G2** | **多段提醒割点（60/30/7 天）而非单一提前量** | AnnualVault / WarrantyVault | 中高——年检/保修/续签类事项需要"提前预警 + 临近催促"两段 | 低（提醒规则增加 `leadStages: number[]`） |
| **G3** | **预算分类限额与超限告警** | OpenFamily | 中——现有支出趋势只做事后分析，缺"事前限额" | 中（新增设置项 + 月度聚合比较） |
| **G4** | **购物模式的按过道/分类扫货排序** | OpenFamily / KitchenOwl | 中——现有采购建议只有列表，缺"超市里按区域扫"的动线 | 低（shopping 分类排序 + 勾选态） |
| **G5** | **重要文档"分级可见性 + 身后交接"** | Quicken LifeHub / Everplans / Dalà | 中——家庭成员间"谁能看到哪一项"是真实需求 | 高（依赖宿主权限模型，需先做只读视图层） |
| **G6** | **证件/资产的"存放位置"索引化（家里保险箱/银行柜/云盘）** | OurFamily / Grocery 类 | 中——`copy_location` 已有局部实现，缺全局检索视图 | 低 |
| **G7** | **老年成员健康趋势（血压/血糖）与用药打卡闭环** | 智辰家纪事 / Dalà | 中高——已有 medicine 模块，缺"读数趋势 + 打卡未打提醒" | 中 |
| **G8** | **垃圾回收/市政日程订阅** | Yuvomi | 低中——中国城市差异大，可用 ICS 导入替代 | 低（复用 ICS 解析） |
| **G9** | **积分奖励与零花钱账本（儿童激励）** | Yuvomi / OpenFamily | 低中——allowance 模块已有金额，缺"任务完成 → 积分/零花钱"闭环 | 中 |
| **G10** | **对外 API / MCP 端点供 AI 与外部工具读取** | Yuvomi / Oikos | 中——思源生态已有 `window.LvHome` 桥，但缺**标准化的本机读取端点** | 中（需宿主支持，暂列观察） |

## 四、与既有路线的合并结论

1. 本轮**不引入新模块**，全部在既有 31 模块之上做能力深化（符合"模块=数据、能力=纯函数"的既有架构）；
2. G1/G2/G4/G6 四项成本低、价值明确，构成本阶段主粮；
3. G7/G3 需要新的聚合视图，放在主粮之后；
4. G5/G10 依赖宿主权限与 API 能力，维持观察池，先写清"用户结果 / 依赖 / 停止条件"再启动；
5. 所有新能力必须遵守既有门禁：纯函数 + 单测、i18n 双语、230KB gzip 预算、访客只读兼容。
