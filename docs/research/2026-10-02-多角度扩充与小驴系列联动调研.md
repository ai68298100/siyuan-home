# 2026-10-02 多角度扩充与小驴系列联动调研

## 结论与边界

当前主线提交为 `10eccfe`，本轮只做规划与证据整理，没有源码、构建、测试或思源数据变更。现有项目已经完成 31 个模块的 schema 注册，但“有 schema”只代表字段目录和建库输入存在，不能等同于模块已可用；可交付能力仍应以“录入→持久化→读取→提醒/处理→重启恢复”的证据为准。核心顺序是先保证数据写入、失败补偿和可恢复，再做跨模块聚合；先测量真实交互和扫描成本，再决定预算；先验证平台与插件契约，再对外宣传。

本轮新增 160 个候选项由主 TODO 承载：功能/流程 F01–F20、性能 PF01–PF20、UI 交互 UI01–UI24、31 模块 MD01–MD31、生态 EC01–EC30、宣传 CM01–CM20、质量 Q01–Q15。报告不复制这些任务的逐条文字，避免形成第二份事实源；这里记录它们的分组逻辑、验收口径和来源边界。此前第 35 组 H/D/V/P/T 60 项继续有效，本轮项目是补充其落地场景和外部协作前置条件。
> 本报告保留第 36–42 组的历史调研范围。其后第 43–46 组新增 181 项见 [第二轮产品调研](./2026-10-02-第二轮产品调研与待办延伸.md)，第 47–50 组再新增 112 项见 [生活阶段、服务治理与跨地区调研](./2026-10-02-生活阶段服务治理与跨地区产品调研.md)；最新统计统一以 TODO 底部为准。

性能项不提前承诺 60fps、某个 INP 或固定包体；先锁定样本和测量方式。宣传项不替代质量项，生态项不绕过核心数据恢复。

第一性原则可压缩为四个问题：数据是否真的写入并能恢复，流程是否允许撤销和重试，用户是否知道下一步和失败原因，外部接口是否真的在当前版本可用。任何候选若不能回答其中一个问题，只保留为调研或产品决策，不进入“已支持”。候选的依赖标记沿用 H（提醒/运行态）、D（数据/建库）、P（业务场景）、R（平台/发行）、T（测试）和本报告的新组号；依赖不是版本承诺。

F 组流程项不应被实现成一个“大而全”的项目管理器。事项包只保存来源记录、当前状态、负责人和下一步入口；模块台账仍是事实源。PF 组要把一次扫描拆成读取、解析、合并、持久化、通知五段，分别测量失败和耗时；不要用入口 bundle gzip 代替全包、首开和长会话测量。UI 组先写状态机（空、加载、成功、部分失败、陈旧、重试、已撤销），再画颜色和卡片，移动端触摸目标、键盘 focus、读屏名称与错误 aria-live 需要同一验收表。CM 组每一条文案必须能回链到截图、测试记录或发行包，演示数据必须是虚拟家庭，不能用真实姓名、证件号、健康备注或金额。

生态项还需要四个共同字段：提供者版本、能力名、协议版本、注销函数。调用方保存 `providerId + externalRef`，提供幂等键和最后一次结果；对方卸载、降级、只读或接口缺失时显示“未连接/暂不可用”，不清空已有本地数据。任何跨插件写入都要有用户触发或明确授权，禁止在打开总览时暗中创建联系人、打卡项目、卡片或考试记录。所有广播事件都必须定义是否可补拉、是否跨窗口、是否只在同一 Kernel 生效；eventBus 和 window 事件都不能被当作多设备同步协议。

## 31 模块覆盖的取舍

MD01–MD31 对应 `members/certs/health/social/insurance/exams/pets`、`assets-real/assets-virtual/shopping/memberships/contracts`、`medicine/stock/favors/chores/food/address/bookmarks/snippets/house`、`parenting/schooling/allowance`、`vehicles/transit/travel-plan/travel-booking/travel-packing/travel-log`、`media`。本轮的共同规则是：记录实际发生与来源，支持更正和历史，不把空字段推断成事实；医疗、疫苗、退休、社保等政策字段保存来源、版本、生效/复核日期，提供人工核对入口，不给出新的医疗建议或自动补种判断。

典型增量包括：证件的办理材料与取得新证分阶段；购物订单按分项处理部分收退货后再转资产/库存；搬家时地址、住处、服务账户和物品位置保留旧版本；课程按学期记录课时、请假和补课；车辆维护可研究日期与里程双条件但只使用用户输入；影音将弃看、暂停、重读和每次起止日期分开。上述是业务模型候选，不能因为字段已在 schema 中就宣称已实现。

## 四条组合场景与分阶段策略

1. **证件办理**：成员→证件→材料/预约→附件→提醒→取得新证。先做成员稳定 ID、证件行和附件持久化，再做办理状态；不接政务查询，不自动判断材料齐全。
2. **购物收货转档**：购物订单分项→已收→实物资产或库存→保修/效期提醒。先保证来源 ID 和幂等转档，再做批次、部分退货和统计；失败可从订单继续。
3. **搬家**：地址版本→住处服务账户→资产位置→合同/会员通知→旧住处归档。先做预览、逐项确认和回滚，禁止批量字符串替换导致历史地址改变。
4. **学习链**：schooling 课程/考试→小驴考试统计→闪卡复习→打卡实际事件。先做只读能力探测和用户确认，再做单向记录；没有补拉、版本和幂等证据时保持手动入口。

阶段顺序：先完成 D01–D12、H01–H16 的核心读写/扫描/恢复，再选择一条组合场景做纵向切片；随后做 PF/UI 的测量与可访问性；最后才制作 CM 素材与 EC 扩展。31 个 schema 不能同时承诺 31 个交付模块。

本轮暂不吸收的方向也要写清：不做政务、保险、交通或医疗机构的实时数据抓取；不把密码、完整证件号或健康诊断写入插件；不做云端账号、聊天和多人实时协同；不因竞品有条码、邮件解析、地图或自动用药建议就直接加入。思源图片 OCR 仅作为用户按需触发的宿主能力，AI 模式逐次确认外发，结果不自动回填敏感字段；这不构成自动资料录入或医疗识别能力。其他新能力只有在授权模型、隐私边界、离线行为和可撤销路径明确后，才重新进入调研。对医疗和政策资料，插件只保存用户的人工记录、原始附件、来源链接、版本和复核日期；“提醒”是对用户已录入日期的机械处理，不能替代医生、疾控部门、学校或办事机构的决定。

质量组 Q01–Q15 的共同数据集建议包含：空工作区、一个成员、两个同名成员、停用模块、坏设置、缺列台账、201 行以上台账、错误日期、跨日时区、断网、重复点击、跨窗口写入、插件卸载重装和历史附件。每个案例都记录预期不变量，例如“来源行至多生成一个目标行”“失败不会清空输入”“禁用只隐藏不删除”“已处理生日次年恢复”“单模块失败不抹掉其他模块结果”。回归脚本应同时保存机器可读结果和脱敏截图，失败时指向端点、阶段与恢复动作，而不是只报一个红色总状态。

生态联动的最小纵向切片建议先选只读：总览读取打卡或考试统计，用户点击后再进入提供方；第二阶段再做用户明确点击的单次写入；最后才研究批量同步和后台事件。这样可以把“接口存在”“同一窗口可调用”“跨窗口可补拉”“多设备可恢复”四个层级分开。若某插件没有快照或版本协商，管家保留手动录入和复制链接入口，不把临时事件当成持久事实。所有对外能力都要在设置页显示连接状态、提供方版本、最近成功时间和断开原因。

对外说明建议使用三层标签：已实现（源码和回归证据）、可试用（真实实例走查但兼容范围有限）、规划中（schema 或设计存在，尚未形成闭环）。截图和演示只展示已实现或明确标“概念稿”的内容；GitHub Release 正文写清版本、已知限制、迁移和数据备份方法，social preview 只承担项目定位，不暗示医疗、同步或权限隔离能力。每次从候选进入开发前，先把验收、依赖、失败恢复和停止条件写回 TODO，再创建实现任务。
