> **本文同时标记当前生产状态和目标体验**。`已实现` 表示生产代码已有可用路径，`部分实现` 表示入口或基础链路存在但结果/恢复未闭合，`规划` 表示设计目标，不代表当前版本已有。

## 10. 可用性规范

| 场景 | 规范 |
|---|---|
| 空状态 | 每个视图给"下一步动作"型空态（如成员空→"先添加自己"），不放装饰性空图 |
| 危险操作 | 删除成员/禁用模块（含数据时）/删台账行 → 确认对话框，文案说明数据去向（归档不删优先） |
| 加载 | 台账嵌入视图骨架屏；提醒列表本地缓存优先渲染再刷新（不闪白） |
| 错误 | toast（3s）；批量失败聚合到设置·关于·诊断，不打断主流程 |
| 快捷键 | `打开管家面板` 可配置；`快速记录` 可配置；不做更多全局键避免冲突 |
| 可达性 | 全部交互元素可键盘到达（焦点态用 b3 原生焦点样式）；图标按钮带 title/aria-label；颜色分级 🔴🟠🟡 同时有文字级别冗余，不单靠颜色传义 |
| 文案 | 全部走 i18n；金额/日期本地化格式；证件号等敏感字段默认脱敏显示，点击可见 |

## 11. 内容、AI 与能力状态

### 11.1 页面状态文案

每个模块和筛选结果至少区分：有数据、当前为空、尚未扫描、缺库、部分失败、无权限、陈旧、待确认、草稿、已应用和结果未知。文案应包含当前范围、影响和下一步动作；“暂无提醒”不能代替“尚未接入提醒扫描”。

模块卡和设置页建议分别展示 schema、provision、provider、reminder、AI、evidence 六项状态。这样用户能知道“字段目录存在”与“当前能扫描并提醒”是两件事。

### 11.2 AI 入口（规划）

AI 只从具体任务进入：解释提醒、查找依据、整理录入草稿、比较资料变化、准备办理材料和生成交接草稿。入口先显示本次使用的成员、模块、来源、时间范围、敏感字段和已验证能力；结果分为事实、建议、未知、草稿和待应用修改。生成不等于写入，应用前必须显示差异、目标版本和逐项回执。

思源 Agent 尚未接入生产页面；Agent 不可用或用户关闭 AI 时，查看原文、手工录入、提醒处理和导出仍必须可用。

### 11.3 页面验收主路径

```text
新工作区 → 引导 → 建库 → 新增证件 → 看到提醒
→ 查看来源 → 延后/续期 → 获得操作回执 → 失败可恢复
```

只有这条路径在桌面、移动端和异常状态下都能留下证据，才继续扩展搜索、事项工作台、资料中心、收件箱和 AI 草稿入口。完整 PX 页面契约见 [12 工作台页面与内容架构](./12-工作台页面与内容架构.md)。
