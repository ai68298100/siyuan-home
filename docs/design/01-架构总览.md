## 1. 设计目标与非目标

**目标**

1. **到期不慌**：全家所有"日期敏感"的事（证件、药品、保单、订阅、年检、缴费、生日、退休）在一个面板里提前可见、可处理。
2. **家事有账**：家庭资产、物品、人情、健康、教育、生活的台账，本地优先、可检索、可统计。
3. **一键可查**：任何一条记录按成员、按模块、按时间都能快速定位；常用信息（地址/网址/常用语）一秒取出。

**非目标（同样重要）**

- 不做数据源替代者：违章、保单余额、社保余额、航班动态等以官方渠道为准，本插件只做手动台账。
- 不做多人实时协作：家庭"共享"靠思源同步 + kernel broadcast（远期），不做实时协同编辑。
- 不做内容平台：不抓取媒体元数据、不做在线播放、不做社区。
- 不做记账流水与预算：仅保留台账中的金额字段。

## 2. 设计原则（六条）

| # | 原则 | 落点 |
|---|---|---|
| P1 | **数据不锁定**：一切台账是思源数据库（行=块），用户可见可改可自建视图；插件私有存储只放设置与运行态 | ADR-1/7 |
| P2 | **提醒是灵魂**：提醒中枢是插件的身份；提醒从台账**派生**，绝不要求用户二次录入 | ADR-2 |
| P3 | **成员贯穿一切**：成员库是全局关系枢纽，所有模块台账通过关系列挂成员 | 02 §2 |
| P4 | **宽品类、浅默认**：31 模块全覆盖，默认仅开 5 个；未启用不建库、不进 UI、不进提醒 | MODULES.md |
| P5 | **思源原生观感**：b3 组件与 CSS 变量；台账视图复用原生数据库视图；长内容用思源模板；自绘 UI 仅做聚合与粘合 | ADR-4 |
| P6 | **每层可扩展**：模块=注册表数据、字段=字典、生态=RPC；新能力优先加数据而非改代码 | 05 |

## 3. 分层架构

```
L0 价值层    到期不慌 · 家事有账 · 一键可查
─────────────────────────────────────────────────────
L1 信息架构  管家 Tab（总览│提醒│台账│成员）· 设置 · 快速录入
─────────────────────────────────────────────────────
L2 模块系统  注册表(31) → 生命周期(registered→enabled→provisioned) → 建库器
─────────────────────────────────────────────────────
L3 数据层    思源数据库(台账) · 文档+模板(长内容) · 附件 · 插件设置(loadData)
─────────────────────────────────────────────────────
L4 服务层    提醒中枢(规则/扫描/通知) · 建库器 · 统计聚合 · 生态 RPC(kernel.js)
─────────────────────────────────────────────────────
L5 UI 层     Tab 面板(Svelte 5) · 对话框 · 详情抽屉 · b3 组件/CSS 变量
─────────────────────────────────────────────────────
L6 扩展层    字段字典 · 自定义模块(v2.x) · 生态 API · kernel 服务 · 导出/年报
```

## 4. 信息架构

```
顶栏 🏠 按钮 ──────────────┐
命令面板 "打开管家面板" ────┤
                          ▼
              ┌─ 管家 Tab（常驻工作区，可钉在布局）─┐
              │  [总览] [提醒•3] [台账] [成员]      │
              │   ├ 总览：到期摘要+成员chips+快速记录+模块卡 │
              │   ├ 提醒：完整列表+筛选+处理动作（提醒中枢） │
              │   ├ 台账：模块选择 → 原生数据库视图（嵌入）   │
              │   └ 成员：成员卡 → 跨模块时间线下钻          │
              └───────────────────────────────────┘
快速录入（不进面板）：顶栏⚡ / 命令 / 块菜单右键 / 斜杠 /lv
设置（Dialog）：模块开关 │ 成员 │ 提醒提前量 │ 生态 │ 关于
```

- **总览**是默认页：回答"现在有什么要办的"。
- **台账**尽量复用思源原生数据库视图（ADR-4），插件只提供模块切换外壳。
- **成员**页是 P3 原则的 UI 体现：以人为线索跨模块聚合。

## 5. 架构决策记录（ADR）

| ADR | 决策 | 理由 | 备选与放弃原因 |
|---|---|---|---|
| 1 | 台账承载 = 思源数据库，拒绝插件私有 JSON | 行=块可双链；用户原生可编辑；随工作区同步备份 | loadData 私有 JSON：数据孤岛，用户不可见 |
| 2 | 提醒 = 从台账派生（schema 声明日期字段，中枢扫描），不做手动提醒列表 | 免二次录入；模块开关自动收敛提醒范围 | 手动提醒：与台账脱节，两套数据 |
| 3 | 建库 = 数据驱动 provisioning：模块定义携带 schema，一键建库 | 新模块成本=注册表+schema；升级幂等 | 手工建库：31 模块不可维护 |
| 4 | 台账视图 = 嵌入原生数据库视图；自绘 UI 仅限总览/提醒/详情抽屉/快速录入 | 不重造表格与筛选；观感一致 | 自绘表格：开发量大且丢原生能力。**数据层建库路径已 Spike 定案（2026-10-01，docs/testing/spike-R1R2.md）；前端嵌入方式在 C4 定案，外壳可先走"在文档中打开"** |
| 5 | 建库落点 = 专用笔记本（默认"🏠 小驴管家"，可在设置改目标笔记本），每模块一个文档承载一张数据库 | 用户可见、可同步、可备份；不污染用户笔记 | 散落用户当前笔记本：查找困难 |
| 6 | 到期扫描优先 kernel.js 定时任务，前端心跳兜底（移动端=打开面板时刷新） | 内核常驻可靠；桌面端关窗也能算 | 仅前端心跳：依赖窗口存活 |
| 7 | 插件存储（loadData）只放：settings（开关/成员引用/提前量/引导状态）+ 提醒运行态（snooze/lastNotified/已办缓存） | 业务数据全在思源侧，卸载插件不留孤岛 | 存业务数据：违背 P1 |

## 6. 工程结构规划（src/ 演进）

```
src/
├── index.ts              # 插件入口：Tab/命令/菜单注册、生命周期
├── kernel.ts             # 内核侧：定时扫描、生态 RPC、broadcast
├── core/
│   ├── modules.ts        # 模块注册表（31 项，含 schema 引用）
│   ├── schema.ts         # (v0.2) 字段字典 + ModuleSchema 类型
│   ├── provisioner.ts    # (v0.2) 建库器：幂等创建数据库/模板
│   ├── settings.ts       # 设置读写与默认值
│   ├── hub/              # (v0.2) 提醒中枢：rule.ts / scanner.ts / notify.ts
│   ├── siyuan.ts         # (v0.2) 内核 API 封装（SQL/数据库/块/通知）
│   └── members.ts        # (v0.2) 成员库访问层
├── modules/<id>/         # (v0.2+) 模块专属逻辑（默认视图、特殊动作）
└── panels/               # UI：tab-panel.svelte、overview、reminders、ledger、members、quick-capture、settings、onboarding
```

## 7. 与小驴系列的边界

- 快切/打卡/人脉/拾遗 通过 05 §生态 API 访问本插件，**不直接读其数据**；本插件对它们同理。
- 联动数据（如"维修师傅→人脉联系人"）只存对方 ID 引用，缺失时降级为纯文本。

## 8. 测试与质量策略

| 层 | 策略 |
|---|---|
| 纯逻辑单测 | 周期/周年下次发生日、农历换算、提前量分级（overdue/soon/lead/later）、snooze/mute 合并——提取为无依赖函数，用 vitest 覆盖（含 2/29、腊月廿九、跨年等边界用例） |
| 内核 API 封装 | `core/siyuan.ts` 以注入 mock 的方式单测建库器幂等、补列逻辑 |
| 手动回归脚本 | 每里程碑一份 checklist（引导→建库→录入→提醒→续期→禁用→数据保留），随版本走 `docs/testing/` |
| spike 验证 | R1–R6（05 §6）各出最小样例后再进入正式实现 |
| 质量 | `pnpm run check`（tsc + svelte-check）零错误零警告为合并门槛；无遥测、无埋点，一切数据留在本地 |
