## 提案 A · allowance 愿望清单（TODO §16）

**语义**：孩子的愿望（目标金额）+ 存钱进度。allowance 行是收支事件，愿望是目标实体——不混用。

**存储模型（定案点 1）**：挂 **shopping 模块**——愿望本质是"想买的东西"，与 shopping 天然同域：

- shopping 新增 category 枚举 `wish`（只增枚举，schema 快照 -u）；
- shopping 新增 `target_amount` number 列（只增列，老库自动补）；
- 存钱流水复用 rowlog：新类型 `deposits`（date + amount，通用 appendEntry 语义）；
- **allowance 侧不加任何东西**——存钱动作本身就是一条 allowance 行（category=allowance_al, direction=out），记账与进度各归其位。

**展示（定案点 2）**：shopping 行详情抽屉新增"存钱进度"分区（通用 addRowLogSection）：流水列表 + 头部汇总 `已存 Σ / 目标（进度条）`；达标不自动转"已购"（用户自行处理，不做魔法）。

**验收**：抽屉可见进度条与流水；删除流水重算；CSV 导出含 target_amount；不建新库。

**工作量**：一波（schema 增列 + 抽屉分区 + 测试）。

## 提案 B · 金额显示格式化（TODO §15）

**范围（定案点 1）**：仅"金额语义"列，按**字段字典 key 白名单**——`amount`、`price`、`refund_amount`、`deposit`、`target_amount`（提案 A 新增）。不做 key 启发式（year/rating 等数字列绝不误伤）。

**规则（定案点 2）**：千分位分隔 + 最多两位小数（去尾零）；**不加币种符号**（家庭存在多币种场景，无汇率语义时不猜货币——保持纯数字，单位由列名承载）。

**落点（定案点 3）**：仅**详情抽屉 kv 显示层**；CSV/导入保持机器可读原始值；台账表格维持原样（排序按原始值，避免格式化字符串破坏数值排序）。

**验收**：抽屉金额千分位显示；CSV 值不变；非白名单数字列不变；纯函数 + 单测。

**工作量**：半波。

## 提案 C · 台账搜索拼音/首字母命中（TODO §17，需求观察）

**方案**：`pinyin-pro` 懒加载 chunk（参照 lunar 先例），搜索框对 name/note 列并行匹配全拼与首字母；命中不改变排序（仍 contains 优先）。

**前置**：需求观察——家庭数据量小，contains 已覆盖多数场景；建议真机批使用一段时间后再决定立项。

**工作量**：一波 + chunk 体积预算（估 30–60KB gzip 懒加载，不占首屏）。

## 决策所需

三项均只需用户一句"做 A/B/C"或"不做"；A/B 定案后实现无需再澄清。
