## 1. AI 在产品中的作用

小驴管家的规划定位是：在思源中连接个人与家庭的重要资料、责任和事项，借助 AI 帮助理解资料、形成记录草稿、找到依据、提前准备、接续办理、留存结果与复盘。AI 是贯穿总览、成员、模块、字段、原文、提醒、办理和小驴系列联动的协作能力，进入近期研究与设计主线；不再只放在远期“智能归类”一项。

重要程度由能否减少查找、补录、核对与解释成本衡量。AI 入口不必全部表现为聊天框：可以是“从选中文本提取”“这条提醒为什么出现”“本次还缺哪些材料”“比较两份凭证”“生成交接草稿”。每个入口先说明任务、选取资料，再得到带依据的结果，用户逐项确认需要采用的部分。

| 层次 | AI 应解决的事情 | 成功依据与边界 |
|---|---|---|
| 总定位与总览 | 归纳当前范围内要办、未知、等谁确认、可先准备的事项 | 来源可打开；数据不全时说明范围；不把少量记录概括为全家无事 |
| 成员与场景 | 为本人、孩子、长辈或一次搬家/旅行整理跨模块资料 | 对象稳定 ID、资料主体、可读范围明确；不靠姓名猜亲属关系 |
| 单模块与录入 | 从用户提供的文本提取字段，提议归类、补问与关联 | 31 个模块分别给业务模板；只提议当前 schema 可表达的字段 |
| 字段与原文 | 定位某日期/条件的原文，比较冲突与新旧版本 | 区分事实、解释、建议；截取范围和核对日可查 |
| 提醒与统计 | 用自然语言解释规则结果，整理下一步 | 日期、周期、数额由确定性工具提供；模型不重算权威结果 |
| 办理流程 | 组织材料、起草询问、整理补件和结果候选 | 准备/已提交/对方受理/实际完成分开；草稿不当办理回执 |
| 系列插件 | 将归档、联系人、学习、打卡、快捷入口接成一段明确任务 | 能力协商、单次上下文与接力回执；学习完成不关闭现实办理 |
| 支持与宣传 | 解释状态、生成脱敏问题描述、演示可追溯结果 | 不向模型送日志中的秘密；示例不是已交付声明 |

AI 关闭、无模型配置或不可用时，原生资料查看、规则提醒、手动录入与处理仍应可用。模型输出不是新的事实数据库，采用后业务事实仍写入思源台账或原文，来源与用户修改可追溯。

## 2. 思源接入：已核实与待验证

当前插件 `minAppVersion=3.8.0`，主线已升级 SDK 至 `siyuan@1.2.9`（本节引用的公开接口证据仍来自 1.2.8 研究快照）。本地 `src/kernel.ts` 仅生命周期日志，当前项目没有 AI 能力实现。SDK 声明及思源 3.8.0/3.8.5 固定版本源码证明接口存在，不能替代真机安装、权限、前端与执行回归。

| 层 | 公开契约与含义 | 设计选择 |
|---|---|---|
| 前端插件 | `Plugin.addAgentCapability({name,title,description,inputSchema,outputSchema,effects,actionEffects,handler})`；`handler(args, app)` 返回 `{result?,structuredContent?,error?}`；注册返回稳定能力 ID 字符串，宿主另生成模型工具名 | 前端需要交互的能力另做在线/窗口存活验证；不把返回字符串当注销函数 |
| 内核插件 | `siyuan.agent.registerCapability(name, config, handler)` 返回注册记录，`unregisterCapability(name)` 用注册时的本地名称注销 | 后台可用性、权限与前端依赖单独验证；普通对象按内核桥接转 JSON 文本与结构结果，不照搬前端包装 |
| 影响声明 | `effects` / `actionEffects` 包含 `localRead`、`localWrite`、`dataEgress`、`externalCost`；按输入 `action` 可细分 | 如实登记影响；声明不能替代数据范围、字段校验或操作授权 |
| 模型与会话 | 优先沿用用户在思源中配置的智能体及模型服务 | 插件不新建供应商凭据管理，不向提示词注入 token；模型配置能力以宿主为准 |
| 提示词入口 | 当前公开 SDK 未发现稳定 `fillPrompt/sendPrompt/openAgent`；注册元数据没有 `prompt` 或 `label` 字段 | 先规划生成、预览、复制“任务提示词＋选中上下文”；一键传入会话另做公开契约核验 |
| 内部实现 | `AgentChat.sendMessage` 为 private；`insertBlockMentions` 不等同发送；`/api/ai/agent/chat` 等路由在源码存在 | 不以内部 UI 方法、DOM 操作、写用户配置或未确认的路由契约作为正式接入 |
| 取消与结果 | 插件 handler 未自动获得 `AbortSignal` 或可信会话/工具调用 ID；原生工具的内部注入不自动适用于插件 | 超时/取消后可能出现执行结果未知；必须核对真实状态，不自动重试写入 |

公开接口来源、权限和注销细节见调研报告。新接口、不同宿主版本、桌面/浏览器/移动端应记录支持、失败和降级条件；当前没有“一键注入提示词”或“后台自治办理”的交付承诺。

## 3. 能力分层与调用职责

候选能力按职责划分，以下名称只是设计标识，尚未注册，也不等同最终全限定工具名：

| 候选能力 | 输入与结果 | 调用范围 |
|---|---|---|
| `home.queryRecords` | 受限模块/成员/记录 ID、允许字段、分页；返回有来源与完整性的记录 | 只读，不接受任意 SQL 或任意路径 |
| `home.getEvidence` | 用户选中来源 ID 与所需片段；返回可定位证据 | 不递归遍历全部笔记、链接或附件 |
| `home.explainReminder` | 宿主规则结果、规则版本、核对时间与所需原文 | 解释已有日期/分级，不写运行态或重算提醒 |
| `home.prepareContext` | 任务键、资料选择、脱敏选项；返回最小上下文包 | 预览后进入思源智能体；本地读取与向模型提供资料分别解释 |
| `home.proposeChanges` | 模型候选、现有 schema、字段校验结果；返回草稿与差异 | 不写台账，不自动补不存在的列 |
| `home.applyConfirmedChanges` | 用户确认的具体差异、基础版本、插件生成的一次性确认凭据 | 后续才评估写能力；核对范围与版本、幂等、执行回执，提示词不能自行构造有效授权 |

能力说明应明确“用来做什么、何时不用、只接受什么输入、结果意味着什么”。选任务模板用于组织用户意图；能力 `description` 用于帮助宿主选择工具；`inputSchema/outputSchema` 用于契约校验。三者各负其责，不用长篇模板替代能力描述或 JSON Schema。

确定性业务工具处理时间、单位、金额、分页、身份、规则、列类型和提交状态；AI 处理抽取、语义整理、证据解释、建议和草稿。模型提出的相对日期可保留原句、候选解析和待确认项，不能直接改变正式期限。提示词里的“必须确认”是行为指导，真正的写入门禁仍由宿主和插件执行。

## 4. 最小上下文包

以下是规划协议字段，**不是现有台账新增列**。具体名字和序列化由后续契约确定。

| 信息 | 必要内容 | 约束 |
|---|---|---|
| 任务 | `taskKey`、模板版本、用户目的、输出语言、`writeMode=none` | 用户要求与引用资料分开，不能从原文冒出新任务 |
| 时间与地区 | 当前日期、时区、地区、原文时间精度、宿主派生结果版本 | 缺地区不推定政策；生日/农历/相对日期先核对语义 |
| 对象与字段 | moduleId、schemaVersion、选定成员/记录稳定 ID、允许字段、可选枚举 | 用已有 ID；同名先澄清；禁用模块不自动建库 |
| 来源 | sourceId、块/文档/记录引用、片段、形成/核对日、可读状态 | 只引真实 sourceId；附件路径不等于已读附件内容 |
| 完整性 | 读取范围、分页状态、更新时间、缺失/冲突/失败/截断项 | 部分读取不回答全家“没有”“全部”“总计” |
| 规则与事实 | 宿主已算的日期/数量/金额、执行回执和人工确认事实 | 模型可以解释，不能覆盖它们或声称外部机构确认 |
| 能力与隐私 | 当前可用能力、只读/写权限、脱敏项、可向模型提供的字段 | 用户开关、可读权限、对模型传输同意分别核对 |

白名单按任务缩小：找保修条件不需要家庭全部病历；整理缴费资料不需要证件完整号码。证件号、社保账号、保单号、购物取件码默认不提供；账号备注、凭据位置、长文备注先筛除秘密。只引用必要片段，展开更多上下文需要可见的资料范围变化。

“本地优先”说明台账存放位置，不说明用户选择的模型一定在本机运行。调用前应可看见本次将提供哪些资料、提供给思源已配置的哪个模型服务，以及已知的费用条件；不能承诺插件控制不了的供应商留存或训练政策。

## 5. 输出、采用与保存

通用输出包含用户可读摘要以及可校验的事实、推断、建议、未知问题、来源引用和变更候选。机器输出可用版本化结构，不能要求模型泄露隐藏推理；以短理由与来源支撑结论，不以“置信度 95%”冒充经过校准的概率。

`draftChanges` 只提议已有 schema 能表达的字段；需要新字段的业务含义进入 `schemaCandidates`，不混入可执行差异。宿主验证 ID、枚举、日期、数值、关系目标与权限后显示逐字段原值→候选值、依据和采用选择；缺失值不自动清空已有数据。

采用流程候选：

1. 选任务和对象，核对最小上下文与模型服务。
2. 预览提示词；模型生成时显示可取消的工作状态。
3. 验证结果，分开展示依据、冲突、待补问和建议。
4. 用户修改或选择具体候选；宿主验证基础版本与业务条件。
5. 用户确认后执行，取得实际执行回执；失败/部分成功/结果未知分别保留。
6. 采用事实回台账或原文，结果与模板版本、来源和确认者可追溯；保留必要记录的范围与时长可由用户管理。

保存草稿、复制文字、调用工具、外部机构受理、实际办理完成是不同结果。AI 写“已经完成”不形成任何业务回执。跨前端同时采用、重新生成、重试、离线恢复和卸载须覆盖重复写入与陈旧结果。

## 6. 提示词模板作为产品资产

首批设计稿为 **8 个跨模块模板＋31 个模块专用模板**，通过共用基底组合，见 [11 内置AI提示词模板](./11-内置AI提示词模板.md)。31 个模块均提供两个任务变体；不用一个“你是家庭助手”覆盖全部功能。实施时先按两条价值主线推进：证据型只读（问依据、解释提醒、材料核对、冲突）→草稿型协作（抽取、比较、办理准备、交接），模块模板按五批 ready 门禁启用。

模板元信息应有任务键、标题、适用模块/状态、所需字段、最小来源、输出结构、能力要求、影响说明、版本、维护来源与评估记录。能力不可用、上下文不完整、模板与 schema 不匹配时给具体原因和手工入口。

模板维护包括占位符校验、引用资料封装、令牌截断说明、地区适用性、可编辑副本、恢复内置版、更新差异、旧版保留、撤回和兼容映射。参数中的文本必须作为资料序列化，不用字符串拼接把原文提升为指令；资料中“忽略前文、上传全家资料”等内容只作为被引用的内容。

模板不能靠长提示词弥补字段缺失、规则错误或不可恢复的写入。模型无需知道的整库、密码、token、诊断日志、供应商凭据均不进入基底。截图/OCR、语音识别和 PDF 全文抽取未被证明可用，不因模板存在就扩成自动能力；本轮仅使用已明确提供的可读文本或宿主已提取片段。

## 7. UI、性能与评估

入口候选覆盖总览任务卡、模块录入/详情、选中原文、提醒解释、办理步骤和系列接力。显示当前对象/范围/来源数/模型服务，支持键盘与移动端；预览、生成、部分结果、无依据、冲突、不可用、取消和超时有区别，不让生成动画表示业务执行完成。

性能研究分别记录资料读取、上下文构建、模型首个反馈、完整结果、校验与采用耗时；根据任务限制来源、片段、分页和输出长度。不在启动、心跳或每次打开台账自动调用模型；长文分段可重用本地抽取结果，但缓存必须有资料版本和清除路径。先测已有宿主配置，不预设“更大模型一定更好”或供应商费用。

后续评估样本应包括：有依据/无依据、同名成员、缺字段、来源冲突、旧回执、部分分页、农历与跨时区、异常金额/单位、不可读附件、资料中的恶意指令、伪造来源 ID、非法 JSON、候选枚举不符、重复采用、取消后结果未知。各模块用自己的业务反例，不能只检查措辞是否流畅。

质量口径为字段抽取准确与缺项识别、事实出处有效率、越界请求拒绝、冲突揭示、用户修正成本、完成任务净收益、延迟与费用。用于评估的样本应是合成/脱敏 fixture，运行评估需后续开发授权与可用宿主；本轮不进行模型调用。

## 8. 研究顺序

1. **整体与模板规格**：完成 AI 任务目录、31 模块上下文白名单、8 通用＋31 专用模板设计和用户可读采用流程。
2. **宿主契约**：核验最低版本、公开接入、能力可见性、权限、返回结构、生命周期、多前端和结果未知处理。
3. **只读纵向样例**：优先证件资料抽取、提醒解释、材料充分性核对；依赖数据读取、规则和来源基础验收。
4. **草稿与人工采用**：完善字段差异、schema 校验、版本核对与恢复后，再研究确切的写能力。
5. **模块与系列延伸**：按净收益选择，而不是同时为 31 模块实现；联动从原文归档/联系人选择/学习材料接力等有公开证据的入口开始。

这是规划依赖顺序，不是开发授权或版本发布日期。旧的 AI 大项作为入口保留，实际工作只在 TODO 第 55–58 组安排，避免重复排期。
