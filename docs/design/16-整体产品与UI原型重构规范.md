# 16 · 整体产品与 UI 原型重构规范

> 版本：v1.0 · 2026-10-11 设计基线
>
> 本文把现有的架构、提醒、台账、成员、AI 和视觉规范合并成一套可执行的产品与界面基线。它是设计和开发的总入口，不改变 [01 架构总览](./01-架构总览.md) 中的数据所有权和提醒派生原则，也不把规划能力写成当前已实现能力。
>
> 最新目标体验原型：[prototype/v6.html](../../prototype/v6.html)，视觉层级参考本机小驴闪卡 R54。原型使用合成数据，只展示布局和交互骨架，不代表生产功能已接通；[v5](../../prototype/v5.html) 保留作历史对照。

## 1. 产品定位

### 1.1 一句话定位

**小驴管家是思源里的个人与家庭生活操作系统：把重要资料、持续责任、日常记录和到期事项放在同一个可追溯的闭环里。**

它的价值不是“把所有东西做成表格”，而是让用户在四个时刻都能继续行动：

| 用户时刻 | 管家要回答的问题 | 对应结果 |
|---|---|---|
| 想起一件事 | “我先记在哪里？” | 3 秒完成一条轻量记录，之后再整理 |
| 需要处理 | “现在最该做什么？” | 按人、时间、模块给出下一步，而不是堆一页数字 |
| 需要核对 | “这个信息从哪里来？” | 字段、附件、原文、形成时间和核验状态可回溯 |
| 事情结束 | “以后还能不能找到？” | 结果、费用、凭证、下次日期和关联对象沉淀到原记录 |

### 1.2 产品闭环

```text
捕捉                  整理                  办理                  沉淀
文字/照片/快速按钮  →  归属对象与模块  →  材料/状态/下一步  →  结果/费用/凭证/提醒
       ↑                    │                    │                    │
       └──────── 全局搜索、成员关系、AI 草稿、时间线持续回流 ─────────┘
```

“记录”和“办理”是两种不同动作。购物、加油、参加婚礼可以先快速记下；证件换领、车辆年检、保险理赔需要事项容器承接材料、节点和结果。二者都最终回到同一条可查询的台账事实。

### 1.3 六条产品原则

1. **先给下一步**：首页展示行动和影响，统计只在能帮助决定时出现。
2. **一次录入，多处可见**：快速记录、台账、提醒、成员时间线和搜索引用同一条事实。
3. **浅入口，深详情**：首屏只让用户做少量高频选择；完整字段、来源和历史在详情中展开。
4. **事实与草稿分开**：未确认的手工草稿、AI 建议和导入预览不能进入正式提醒与统计。
5. **默认不打扰**：未启用模块不建库、不出现在首页；提醒按严重程度和责任人分组。
6. **能力诚实**：每个模块都分别显示资料、提醒、统计、附件、AI 和外部联动是否可用。

## 2. 信息架构

### 2.1 一级导航

桌面端使用稳定的左侧导航，移动端折叠为底部导航与“更多”页。导航项数量固定，模块不直接挤进一级导航。

```text
┌────────────── 左侧导航 ──────────────┬─────────────────────────────┐
│ 小驴管家                             │ 当前页面标题 + 当前范围       │
│  总览                                │                             │
│  时间                                │ 主要工作区                   │
│  台账                                │ 列表 / 看板 / 日历 / 详情     │
│  成员                                │                             │
│  收件箱                              │                             │
│  ─────────────                       │                             │
│  AI 协作（可隐藏）                   │                             │
│  设置                                │                             │
│                                      │                             │
│ ＋ 快速记录（固定主按钮）             │                             │
└─────────────────────────────────────┴─────────────────────────────┘
```

| 一级页面 | 页面任务 | 首屏必须有 | 不承担的事情 |
|---|---|---|---|
| 总览 | 决定现在做什么 | 今日行动、待确认、最近记录、模块摘要 | 展示所有字段、承载复杂编辑 |
| 时间 | 安排与处理到期事项 | 日/周/列表视图、筛选范围、状态回执 | 复制另一套提醒数据 |
| 台账 | 查看和管理模块事实 | 模块切换、视图切换、搜索、批量操作 | 把办理流程藏在窄表格里 |
| 成员 | 从人找到所有关系 | 成员卡、责任、跨模块时间线 | 代替模块详情 |
| 收件箱 | 处理刚捕捉的内容 | 待分类、待补字段、疑似重复、失败重试 | 变成第二份永久台账 |
| AI 协作 | 在当前上下文帮用户整理 | 任务、范围、来源、草稿和差异 | 作为无上下文聊天首页 |
| 设置 | 管理范围、数据和运行状态 | 分类导航、当前值、影响、保存回执 | 放置业务录入入口 |

事项工作台、资料依据、车辆工作台等属于二级工作区，从总览、时间、台账或成员进入；只有验证长期高频后才提升为一级入口。

### 2.2 模块分组

| 领域 | 首批模块 | 共同问题 | 默认视图 |
|---|---|---|---|
| 人员与身份 | 成员、证件、联系方式、医保社保 | 谁的资料、何时到期、来源是什么 | 卡片 + 到期列表 |
| 车辆与出行 | 车辆、加油、充电、维护、出行计划 | 车辆状态、费用趋势、下一次维护 | 车辆卡 + 时间线 |
| 财务与保障 | 保险、订阅、人情、资产、合同 | 周期、金额、责任、凭证 | 列表 + 日历 |
| 家庭与生活 | 购物、囤货、家务、地址、常用语 | 快速记录、位置、库存、重复事项 | 清单 + 分组 |
| 健康与教育 | 药箱、疫苗、就医、孩子成长、学校 | 成员、周期、敏感资料、材料 | 时间线 + 状态 |
| 内容与资料 | 影音、书籍、收藏、网址、拾遗 | 进度、来源、标签、回看 | 画廊 + 列表 |

模块注册表继续是唯一事实来源。每个模块除了 schema，还必须声明：`group`、`icon`、`defaultView`、`quickActions`、`requiredContext`、`reminderFields`、`relationTargets`、`capabilities` 和 `privacyLevel`。

### 2.3 统一对象模型

```text
成员 ─────┬──── 记录（一次事实） ──── 来源/附件
          │             │
          │             ├──── 提醒规则（由日期字段派生）
          │             ├──── 事项（跨记录的办理容器）
          │             └──── 统计（按范围实时聚合）
          │
模块 ─────┴──── 视图（列表/看板/日历/画廊/时间线）
```

- **记录**：可独立查询的一条事实，如一次加油、一张证件、一笔人情。
- **事项**：有开始、责任人、材料和结果的过程，如“办理车辆年检”。
- **来源**：原文、附件、链接、人工录入或 AI 草稿的依据，记录取得和核验状态。
- **提醒**：从记录日期字段计算的投影，不新增第二条业务事实。
- **视图**：同一数据的展示方式，不复制数据或状态。

## 3. 统一交互生命周期

### 3.1 新建与编辑

所有模块遵循“选择上下文 → 录入最小字段 → 补充字段 → 预览关系 → 保存回执”的五步结构。

```text
点击新建
  ↓
选择对象：成员 / 车辆 / 家庭 / 无归属
  ↓
填写最小必填：名称、发生/到期时间、核心数值
  ↓
可选扩展：附件、来源、标签、备注、关联记录
  ↓
预览：将生成的提醒、关系和统计影响
  ↓
保存中 → 已保存 / 部分成功 / 失败（保留草稿）
```

“新建”按钮始终有清晰的作用域文案，例如“新建车辆”“记一笔加油”“添加证件”。避免一个无上下文的“新增”把用户送入深层空白表格。

### 3.2 快速记录

快速记录是所有高频事项的统一入口，固定在总览、移动端底部和命令面板。第一屏只问三件事：**记什么、归属谁、何时发生**。保存后可继续补全，不强迫一次填完。

| 快速动作 | 最小字段 | 保存后的联动 |
|---|---|---|
| 加油 | 车辆、日期、里程、油量、金额 | 车辆里程、油耗趋势、费用统计 |
| 充电 | 车辆、日期、里程、电量/金额 | 车辆能耗趋势、费用统计 |
| 维护 | 车辆、项目、日期、金额/下次日期 | 维护时间线、到期提醒 |
| 婚礼/人情 | 对象、日期、金额、往来方向 | 人情记录、成员关系、年度汇总 |
| 购物 | 名称、日期、金额、类别 | 购物清单、资产/囤货候选 |
| 药品 | 名称、成员、有效期、数量 | 药箱库存、效期和低库存提醒 |
| 证件办理 | 成员、证件类型、到期日/事项状态 | 证件台账、提醒、办理事项 |
| 成长事件 | 孩子、日期、事件、备注 | 成长时间线、附件和回顾 |

保存后显示“已记录到哪里”“产生了哪些提醒”“还能补什么”，并提供“继续补充”“查看详情”“再记一笔”三个明确动作。

### 3.3 删除、归档和移动

- **移动**只改变模块或归属，不删除原始事实；显示影响到的提醒和关系。
- **归档**从默认列表隐藏，保留搜索、历史和恢复入口。
- **删除**仅对可恢复对象开放，二次确认显示关联记录、附件和提醒影响。
- 批量操作先显示选择范围，再展示成功、跳过、失败和可撤销时间。

## 4. 页面原型规范

### 4.1 总览工作台

**目标**：5 秒内知道今天要做什么，10 秒内完成一条记录。

```text
┌────────────────────────────────────────────────────────────────────┐
│ 早上好，今天 10 月 11 日       [搜索资料、事项、成员] [＋快速记录] │
│ 当前范围：全家 · 全模块 · 未来 30 天          最近同步 08:42      │
├───────────────┬───────────────────────────────┬────────────────────┤
│ 今日行动  4    │ 待整理 3                      │ 数据状态           │
│ 逾期 1         │ 新捕捉 2 · 待补字段 1         │ 31 个模块 · 2 个待修│
├───────────────┴───────────────────────────────┴────────────────────┤
│ 今日优先事项                                                        │
│ [高] 妈妈身份证       逾期 2 天   查看依据  处理  延后              │
│ [中] 车辆保险         12 天后    查看详情  续期                      │
├────────────────────────────────────────────────────────────────────┤
│ 快速记录  [加油] [充电] [维护] [人情] [购物] [药品] [证件] [更多]   │
├──────────────────────────────┬─────────────────────────────────────┤
│ 最近记录（全宽、默认最近 5 条）                                      │
│ 日期筛选  类型筛选  按日折叠  [显示更多] [查看全部]                    │
│ 10:20  凯美瑞 · 加油 ¥320 · 68,420 km                                │
│ 昨天   儿子 · 成长事件 · 1 张照片                                     │
│ 前天   妈妈 · 医院回执 · 待补下次复诊日                              │
├────────────────────────────────────────────────────────────────────┤
│ 我的模块（全宽、按领域分组手风琴）                                    │
│ ▾ 出行  车辆 1 · 12 条记录 · 2 项待办                                │
│   车辆与出行 / 证件与身份 / 家庭生活 ...                              │
│ ▸ 生活  8 个模块 · 42 条记录 · 1 项待办                              │
└──────────────────────────────┴─────────────────────────────────────┘
```

关键交互：成员范围以紧凑选择器呈现，成员较多时可搜索；时间范围和模块筛选贯穿页面；每个数字旁显示口径与更新时间；无数据、未读取和读取失败使用不同状态。“最近记录”与“我的模块”永远纵向排列，不在宽屏下并排。生产活动列表使用统一只读投影：总览每页 8 条，成员卡内每页 5 条；支持名称/字段/成员搜索、模块筛选、折叠、分页、刷新和真实来源打开。事项日期与录入时间分开标识，不把截止日当成新增时间；成员时间线只汇总确有关联成员的台账记录与流水，提醒仍留在提醒区。首次读取、全量失败、空结果、筛选无匹配和部分模块失败分别有状态反馈与下一步操作。我的模块采用分组手风琴，组头显示模块数、已知记录数、待办数和展开状态；默认展开首组与有待办的组，搜索/筛选自动展开匹配组，用户手动状态只在未筛选时生效。统计未知时显示“待读取”，不能按 0 处理。

当前活动读取服务已将有明确 `schema.activity.dateField` 的台账行和可关联到有效台账行的 `rowlogs` 子记录映射成统一活动项。台账记录优先用思源行返回的真实 `createdAt` 排序；缺少录入时间时回退到事项日期。流水优先用真实 `entry.at` 排序，并同时显示有效流水日期；缺少真实录入时间时按流水事项日期排序。只接受有效日期，空值、非法日期或无可靠时间的项目不伪造时间并从时间线略过；详情摘要只取 schema 明确字段或流水白名单，并限制长度。成员关联依据台账关系 block ID 与成员档案映射确定，不按标题猜测。

这是一份只读、进程内缓存的活动投影，不是独立历史索引或第二份主库。仅扫描已启用且具备活动日期声明、或已有对应流水的模块；活动日期未声明的普通台账行、没有可用日期的记录不会出现。各模块读取受限并发，单模块失败时展示已成功读取的部分、失败数量及重试；若没有任何模块可展示且读取失败，则显示错误和重试；未配置任何可读模块时提供设置入口。缓存与台账版本关联，强制刷新重新读取；活动摘要不会写入同步运行态。跨模块活动的覆盖范围由当前模块 schema、启用状态、数据有效性及权限决定，因此页面说明不应宣称其涵盖所有历史事项。

### 4.2 时间与提醒

提供日历、列表、时间线三种视图。顶部固定显示筛选范围和扫描状态，提醒项必须显示来源字段、责任人、原到期日、当前动作和处理回执。完成、延后、忽略、续期和定位使用不同按钮；不能用一个“处理”吞掉语义。

```text
时间  [列表] [日历] [时间线]  成员▼ 模块▼ 状态▼ 未来30天▼
┌──────────────────────────────────────────────────────────────┐
│ 逾期                                                         │
│ ● 身份证 · 妈妈          到期 09-29   来源：证件.到期日       │
│   [查看依据] [更新日期] [延后] [标记完成]                     │
│ 未来 7 天                                                     │
│ ● 车辆保险 · 凯美瑞      到期 10-18   来源：保单.续保日       │
└──────────────────────────────────────────────────────────────┘
```

### 4.3 台账模块页

台账页顶部是模块上下文栏：模块名、记录数、当前视图、筛选、搜索和主动作。视图切换只改变展示，不改变查询条件。每个列表项提供悬停/触屏动作栏：查看、编辑、复制、归档；批量操作固定在选择条。

```text
车辆与出行  车辆 1 · 加油 28 · 充电 12 · 维护 6
[车辆] [加油] [充电] [维护]     [列表] [卡片] [统计]   [＋新建车辆]
筛选：车辆▼ 能源▼ 日期▼ 标签▼       [搜索当前台账]
┌──────────────────────────────────────────────────────────────┐
│ 凯美瑞 2022                 油电混合   68,420 km              │
│ 粤A·12345  上次加油 10-08    本月 ¥1,260   下次保养 11-20      │
│ [记加油] [记充电] [记维护] [查看车辆] [更多]                  │
└──────────────────────────────────────────────────────────────┘
```

桌面端允许表格、卡片和统计并列；移动端优先卡片，长字段折叠到详情。固定窄抽屉不承载复杂录入，涉及附件、历史、关系和统计的对象进入全屏详情页。

### 4.4 通用详情页

详情页顶部显示对象身份、状态、主动作和关联入口；主体采用“摘要 + 时间线 + 字段 + 来源 + 关系 + 统计”六个区块。字段分为核心、扩展、系统三层，默认展开核心字段。

```text
┌──────────────────────────── 对象详情 ────────────────────────────┐
│ ← 返回台账   凯美瑞 2022      有效 · 最近更新 10-08  [编辑] [...] │
│ [记加油] [记充电] [记维护] [新建事项]                              │
├────────────────────────┬────────────────────────────────────────┤
│ 核心摘要                │ 下一步 / 到期                             │
│ 车牌 · 能源 · 当前里程 │ 保险 12 天后 · 保养 40 天后                │
├────────────────────────┴────────────────────────────────────────┤
│ [概览] [时间线] [记录] [来源与附件] [统计] [关联]                 │
│ 时间线：加油、充电、维护、保险与手工备注按发生时间排列            │
└───────────────────────────────────────────────────────────────────┘
```

### 4.5 新建/编辑页

采用分组表单而非一长条字段。顶部显示进度与草稿状态，底部固定保存栏显示必填缺口和保存结果。日期、金额、里程、数量都必须带单位和示例；证件号等敏感字段支持完整录入、显示/隐藏和复制，不默认截断为后四位。

### 4.6 成员与家庭

成员卡显示头像、关系、待办数、资料完整度和最近活动。进入成员后可以切换“资料、提醒、事项、记录、时间线”，所有模块关系都以成员过滤器复用，不另建成员副本。当前成员卡内的关联记录流按成员台账关系筛选，只代表已关联到该成员的台账记录与流水，不把提醒或未建立成员关系的记录混入；主体、录入者、负责人和共享对象必须分别显示。成员关系缺失时显示“未关联成员”，不根据标题或备注推断归属。

### 4.7 收件箱

收件箱每项有来源、捕捉时间、候选模块、缺失字段和处理状态。支持“采用为记录”“转为事项”“合并到已有记录”“忽略并保留恢复期”。录入失败、AI 失败和导入失败都回到收件箱，不让用户寻找消失的草稿。

### 4.8 全局搜索

搜索默认覆盖当前授权范围，结果按记录、成员、提醒、事项、来源和附件分组。每项显示命中字段和更新时间；搜索语法先用自然筛选器，后续再增加自然语言转查询。无结果时说明搜索范围和可扩大范围的操作。

### 4.9 设置

设置采用左侧大类导航、右侧具体内容，每一页只解决一种决策：

```text
设置
├─ 使用范围       模块开关、目标笔记本、首次引导
├─ 提醒与时间     提前量、静默、视图、通知渠道
├─ 成员与隐私     成员、敏感字段、共享范围、锁定
├─ AI 协作        开关、服务来源、上下文白名单、确认策略
├─ 数据与恢复     导入导出、备份、诊断、缺列和失败重试
├─ 外部联动       小驴系列、日历、联系人、权限
└─ 关于与支持     版本、更新、反馈、日志
```

每页都要有“当前值、影响范围、保存状态、恢复默认”四类信息。模块启停先预览建库、提醒和首页影响，保存后逐项显示成功/跳过/失败；停用不删除数据。

### 4.10 移动端

移动端首屏只保留今日行动、快速记录和最近记录。详情改为全屏页面，操作栏贴近底部安全区；复杂筛选使用底部抽屉，表格转卡片；上传图片先压缩并显示尺寸、方向和失败重试。系统返回键恢复上一级筛选和滚动位置，软键盘出现时保存栏不能被遮挡。

## 5. 车辆模块示例

车辆是“资料对象 + 高频记录 + 趋势统计 + 到期提醒”的完整样板，其他模块按同一生命周期扩展。

### 5.1 车辆工作台

车辆卡必须展示照片（固定比例、单图大小限制、无图占位）、品牌型号、车牌、能源类型、里程、保险/年检、最近一次能耗记录和本月费用。主动作直接提供“记加油、记充电、记维护”，不要求先打开深层台账。

### 5.2 加油/充电快速记录

默认字段为日期、车辆、里程、油/电类型、数量、单价、金额和站点；可选字段为支付方式、优惠、附件和备注。保存时校验里程不能倒退，金额可以由数量×单价建议填充但允许手工修正。记录后立即更新车辆卡、费用卡和趋势图；数据不足时显示“样本不足”，不输出伪精确油耗。

### 5.3 车辆统计

统计页提供费用、能耗、里程和维护四个分段。默认显示最近 3 个月，可切换车辆、能源、时间和是否含异常记录；每个图表同时显示样本量、计算口径、最后更新时间。油耗算法和单位沿用现有数据模型，统计只读记录，不写入第二份汇总。

### 5.4 车辆事项

“年检、保险、保养、维修、事故”使用事项模板：状态、负责人、机构、材料、费用、时间节点、回执和下次动作。车辆详情的时间线同时汇入快速记录和事项结果，但每条事实保留来源类型。

## 6. 视觉与组件规范

### 6.1 视觉方向

采用“安静的工作台 + 清晰的状态色 + 少量领域色”的组合。浅色模式下所有内容卡片、统计卡、模块卡、表单分组、详情、设置和弹层均使用纯白卡面；页面画布使用冷雾蓝（原型 `#f7f8fc`），弱控件表面为 `#f3f5fa`，边线为 `#e6eaf1` / `#d5dde8`，形成区别于小驴打卡的背景识别。主色使用深海蓝，珊瑚橙只用于少量提醒和操作点缀，避免紫黄组合占据界面。弱表面不扩散到整张卡片，主按钮可以继续使用既有强调色。深色模式保留深灰表面层级和清晰描边。危险、警告、成功颜色只落在色轨、图标、状态文字和徽标上，选中控件可保留弱强调色；提示、AI 和逾期内容也保持白卡，通过边线、标题与状态标识表达含义。

卡片层次由细边框、低透明度的柔和阴影和有节奏的留白共同建立：常态使用轻投影，悬停只提高一级阴影并上浮 1px，卡面继续保持纯白。阴影使用中性蓝灰低透明度，普通内容卡不与弹层争抢层次。浅色模式关闭卡内环境光晕和全屏胶片颗粒；背景与白卡的差异应清爽可辨。导航、筛选和主动作使用胶囊形，内容卡保持圆角矩形，避免大面积渐变、过度圆角和漂浮装饰。

### 6.2 尺寸基线

| 项目 | 桌面 | 移动 | 规则 |
|---|---:|---:|---|
| 内容最大宽度 | 1440px | 100% | 内边距 20–28px |
| 侧栏 | 232px | 隐藏 | 收起后保留当前页标题 |
| 卡片圆角 | 16–18px | 16px | 白卡与细描边；详情弹层 20px，避免重复嵌套卡片 |
| 控件圆角 | 10–12px | 10–12px | 导航、分段筛选和主动作使用 999px 胶囊 |
| 内容间距 | 16–22px | 14–18px | 区块间 28–32px，最近记录与我的模块纵向排列并独立折叠 |
| 控件最小触控 | 36px | 44px | 图标按钮提供 tooltip/aria-label |
| 表单列数 | 2 | 1 | 复杂字段分组折叠 |
| 动效 | 120–240ms | 120–180ms | 支持 reduced-motion |

组件命名、主题 token、焦点和状态矩阵继续以 [07 视觉设计语言](./07-视觉设计语言.md) 与 [08 UI 组件库](./08-UI组件库与实现规范.md) 为准；本规范增加“上下文栏、快速动作条、保存回执条、证据卡、关系卡、时间线项”六个业务组件。

### 6.3 状态视觉语法

| 状态 | 颜色 | 必须同时显示 |
|---|---|---|
| 正常/有效 | 绿色 | 更新时间或有效期 |
| 即将到期 | 黄色 | 剩余时间和下一步 |
| 逾期/阻断 | 红色 | 逾期天数、原因和处理动作 |
| 草稿/待确认 | 紫蓝 | 来源、缺口和确认动作 |
| 陈旧/部分失败 | 灰橙 | 可用范围、影响和恢复动作 |
| 未配置 | 中性灰 | 需要配置的具体入口 |

## 7. AI 扩展位

AI 是当前页面里的协作层，不能代替导航和核心手工操作。每个 AI 入口都显示任务名、对象、使用字段、来源快照、隐私范围和人工替代路径。

| 页面 | AI 入口 | 生成结果 | 写回门禁 |
|---|---|---|---|
| 总览 | 解释提醒、准备下一步 | 依据说明、待办草稿 | 用户逐项确认 |
| 快速记录 | 从文字/图片识别字段 | 录入草稿、缺字段提示 | 差异预览后保存 |
| 事项 | 整理材料、生成清单 | 材料清单、沟通草稿 | 不自动提交外部机构 |
| 车辆 | 分析费用/能耗变化 | 趋势解释、异常候选 | 显示样本和计算口径 |
| 收件箱 | 分类、补字段、查重 | 候选关系和合并建议 | 用户选择目标记录 |
| 搜索 | 自然语言转筛选 | 可复用查询条件 | 先展示查询范围 |

AI 结果分成“事实、引用、建议、未知、草稿”五层；来源变化、权限变化、服务未配置、请求失败和用户取消都撤回旧结果并保留手工路径。敏感证件号、健康资料、照片和家庭成员资料默认不发送，除非用户明确选择并能看到范围。

## 9. 设计验收清单

每新增一个模块或页面，必须回答以下问题并留下证据：

1. 用户从首页、快速记录、台账和搜索能否在两步内到达？
2. 新建、编辑、查看、复制、归档、删除和移动的语义是否分开？
3. 保存成功、部分成功、失败、取消、陈旧和恢复是否都有明确去向？
4. 记录是否同时出现在正确的提醒、成员、时间线和统计范围？
5. 空态是否告诉用户为什么为空，以及下一步做什么？
6. 移动端单手操作、软键盘、返回键和长字段是否可完成？
7. AI 不可用时，用户能否完整完成核心手工任务？
8. 原型、生产状态、测试证据和版本说明是否一致？

原型图只描述目标体验；生产状态仍以源码、真实思源内核、桌面/移动端回归和 [13 原型质感与实现差距](./13-原型质感与实现差距.md) 的契约为准。
