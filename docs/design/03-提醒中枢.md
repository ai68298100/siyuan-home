# 03 · 提醒中枢（Reminder Hub）

> 自上而下设计 · 第四层（L4）。插件的灵魂能力：**提醒从台账派生，绝不二次录入。**
> 前置阅读：[01 架构总览 ADR-2/6](./01-架构总览.md) · [02 数据模型 §2 字段字典](./02-数据模型与模块规格.md)。

---

## 1. 概念模型

```
规则 Rule（模块 schema 声明）          运行态 Reminder（派生，不落库）         处理 Action
┌──────────────────────┐    扫描    ┌────────────────────────┐         ┌─────────────────┐
│ moduleId             │ ────────► │ id = rowId+ruleKey      │ ──────► │ 完成 / 续期      │
│ sourceField (expiry/ │  (定时)    │ title（行 name）        │         │ 延后 snooze N天  │
│   due/next_billing…) │           │ memberId / dueDate      │         │ 定位 openTab 行  │
│ kind: oneoff /       │           │ daysLeft / 级别 🔴🟠🟡   │         │ 忽略此类 mute    │
│   recurring /        │           │ status: upcoming/due/   │         └─────────────────┘
│   anniversary        │           │   overdue / snoozed     │              │
│ defaultLeadDays      │           └────────────────────────┘              ▼
│ repeat / lunar       │                                    处理记录写回台账行 + 运行态
└──────────────────────┘                                    （snooze/已办缓存在插件存储）
```

- **oneoff**（一次性效期）：证件到期、合同到期、试用期截止。
- **recurring**（周期）：缴费日、家务、保养、囤货补货——按 `cycle` 从 `last_done`/`date` 推算下次 `due`，**中枢可写回台账的 due 列**。
- **anniversary**（周年，支持农历）：生日、纪念日、忌日——每年重复；农历用 lunar-typescript 换算公历后参与扫描。

## 2. 提醒规则声明（数据驱动）

模块 schema 的 `reminders` 字段声明规则，中枢只认声明，不写死模块：

```ts
reminders: [
  { key: "expiry",        field: "expiry",        kind: "oneoff",      leadDays: 90 },
  { key: "warranty",      field: "warranty_expiry", kind: "oneoff",   leadDays: 30 },
  { key: "next_pay",      field: "next_pay",      kind: "recurring",   leadDays: 14, cycleField: "pay_cycle" },
  { key: "birthday",      field: "birthday",      kind: "anniversary", leadDays: 7, lunarField: "lunar" },
]
```

用户可在设置中按 `moduleId.ruleKey` 覆盖 `leadDays`（设置字段 `leadOverrides`）；单条记录可用行的 `remind_before` 列覆盖模块默认。

> 类型定义已落在 `src/types/index.ts`（`ReminderRuleSpec` / `Reminder` / `HubState` / `ReminderLevel`），本文保持语义描述，代码为权威。

## 3. 扫描管线

```
触发源（三路，取并集）
 ├─ kernel.js 定时：每日 08:00（可配）→ 全量扫描 → 写 hub 状态 + broadcast 通知各端
 ├─ 前端：管家 Tab 打开/切回时刷新（移动端主路径）
 └─ 前端兜底心跳：桌面端每 30min（仅当 kernel 侧不可用时启用）
        │
        ▼
扫描器 Scanner
 ├─ 取启用模块清单（settings.enabledModules）
 ├─ 每模块调用其 DataProvider.collectReminders()：内核 SQL 查询台账数据库中
 │    expiry/due/next_billing 等列 ∈ [today - ∞(overdue), today + maxLead] 的行
 ├─ 对 recurring/anniversary 计算下次发生日（农历换算）
 └─ 合并 → 去重（id）→ 套用 snooze/mute → 按成员与日期排序
        │
        ▼
聚合结果 HubState（内存 + kernel storage 缓存）
 ├─ 分组：已逾期 / 未来 7 天 / 未来 30 天 / 更远
 └─ 统计：总数、按成员、按模块（供总览卡片）
        │
        ▼
通知 Notify（桌面）
 ├─ 每日摘要一次：今日新增的 due/overdue 汇总成一条系统通知（lastNotifiedDate 去重）
 ├─ overdue 首次发现立即通知
 └─ 点击通知 → 打开管家 Tab 提醒页；静默时段（默认 22:00–08:00）只入列不弹
```

移动端降级：无系统通知权限 → 总览与 Tab 内红点角标 + 列表。

## 4. 级别与降噪

| 级别 | 条件 | 呈现 |
|---|---|---|
| 🔴 已逾期 | daysLeft < 0 | 置顶、通知、总览红色计数 |
| 🟠 将到期 | 0 ≤ daysLeft ≤ 7 | 高亮 |
| 🟡 提前量内 | 7 < daysLeft ≤ leadDays | 正常列表 |
| ⚪ 更远 | > leadDays | 默认折叠 |

降噪规则：① 分组折叠 + 每组默认显示前 5 条；② `mute`（忽略此类）：按 rowId+ruleKey 静默，列表可显示已忽略项（可恢复）；③ snooze 优先级高于 mute；④ 成员过滤器与模块过滤器持久化，下次打开保持。

## 5. 处理动作语义（到期闭环）

| 动作 | oneoff | recurring | anniversary |
|---|---|---|---|
| **完成** | 行 status→archived（或清除 expiry） | 写 `last_done`，中枢重算 `due` 并写回 | 标记今年已办（运行态），明年自动重现 |
| **续期** | 弹出小窗：新到期日 + 可选记入 `note`（旧日期追加历史），写回行 | — | — |
| **延后** | snooze N 天（N=1/3/7/30），仅运行态 | 同左（不改变真实 due） | 同左 |
| **定位** | 打开台账 Tab 并滚动/高亮该行（openTab + av 定位，v0.2 spike 确认能力） | 同左 | 打开成员页 |
| **忽略此类** | mute 该 rowId+ruleKey | 同左 | 同左 |

所有动作只改**台账行本身**或插件运行态，不产生影子数据。

## 6. 边界与失败策略

- 模块数据库被用户删除 → 扫描器跳过并在设置中标记"台账缺失，点此重建"（provisioner 幂等重建）。
- SQL 字段变更/行被手动改坏 → 单条失败不影响整批，错误聚合到设置页"诊断"区。
- 时区：以内核本地时区为准；农历换算库固定版本，升级需回归生日提醒用例。
- 性能：扫描为增量 SQL（日期范围索引），31 模块全开 < 50ms 量级；kernel storage 缓存供各端读。
