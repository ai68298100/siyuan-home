## 1. 先区分六种用户问题

| 用户问题 | 页面/入口 | 结果 |
|---|---|---|
| 现在最需要处理什么 | 总览 | 少量有优先级的下一步，说明依据和影响 |
| 哪些日期或规则触发提醒 | 提醒 | 规则、源字段、处理/投递状态可解释 |
| 哪些事情正在办理 | 事项工作台（候选二级页） | 材料、提交、等待、补件、结果和后续义务连续可见 |
| 某个事实从哪里来 | 资料/依据中心（候选二级页） | 原文、附件、版本、引用位置和适用时间可回源 |
| 刚才捕捉的内容还没整理什么 | 收件箱（候选入口） | 未分类、待确认、重复候选和已归档有明确去处 |
| 数据是否健康、能否恢复 | 健康与恢复（设置内独立页） | 缺库、缺列、部分失败、待补偿、备份/导出状态可操作 |

当前四个 Tab 仍可作为首屏骨架，不立即扩成八个顶级 Tab。事项、资料、收件箱先从总览/提醒/台账的二级入口进入；只有真实流程证明长期频繁使用，才升为常驻导航。这样保持“家庭档案 + 到期提醒 + 事务工作台”的定位，同时避免把所有能力堆在首页。

## 2. 页面职责和不应混淆的概念

### 总览：回答“现在怎么办”

总览只显示少量可行动卡片：逾期、近期到期、正在办理、待确认、数据健康。每张卡必须显示对象、责任人、依据数量、更新时间和下一动作；“暂无提醒”不能暗示“没有未完成事务”。卡片可按成员或事项聚合，但展开后回到同一来源记录。

### 事项工作台：回答“这件事办到哪了”

事项是跨会话的办理容器，可关联记录、来源、材料、负责人、机构、时间节点、回执和后续义务。它与提醒不同：提醒由日期规则派生，事项记录用户主动开始的办理。最小状态为准备中、待提交、已提交待受理、补件、部分结果、已完成、取消/放弃、结果待复核；状态转换均需要用户事实或机构回执。

### 资料/依据中心：回答“为什么这样记录”

资料中心按来源、对象、版本和适用区间浏览。字段详情旁显示来源片段和“当时采用/持续参考”意图；原文改动、附件不可读、权限失效或版本冲突进入待复核。它不复制全文，不把搜索命中当事实，不因引用链接可打开就宣称权限和内容仍有效。

### 收件箱：回答“刚才留下的内容去哪了”

收件箱接收用户主动捕捉的文字、块引用、待整理草稿和失败重试结果。每项明确来源、取得时间、所属对象候选和当前状态：待分类、待补字段、疑似重复、已采用、已归档、已丢弃。收件箱不是第二份台账；采用后保留来源关系，丢弃也留下可选恢复窗口。

### 成员与时间线：回答“谁的什么经历”

成员页保留人员入口；时间线作为成员卡和事项详情中的二级视图，按实际发生/形成/采用/核验时间分层，不把补录时间当事件发生时间。相同成员名、关系改变、资料主体与办理负责人必须分别显示。

### 健康与恢复：回答“现在是否可信、怎么修复”

诊断页面从设置中的简单提示升级为分级的健康清单：可用、陈旧、部分失败、缺列、无权限、需要用户选择、待补偿、可恢复。每项给影响范围、最近成功时间、原始错误类别和下一步；“重新扫描”不应替代修复原因说明。

## 3. 全局交互骨架

1. **上下文条**：页面顶部显示当前成员范围、模块、时间范围、数据状态和刷新时间；跳转到详情后保持上下文，返回时可恢复筛选与滚动位置。
2. **全局搜索**：结果分为记录、原文/附件、事项、提醒和成员；每个结果标对象、来源、权限、更新时间和命中范围。搜索不扩大本次已授权范围，也不将最近搜索泄露到共用设备。
3. **动作分层**：查看来源、形成草稿、创建事项、修改字段、提交外部机构、标记完成使用不同按钮和确认语义。复制链接、打开文档、生成草稿都不能显示为已办理。
4. **详情抽屉与专页阈值**：短记录用抽屉，含多个来源/材料/状态/回执的事项用专页；关闭抽屉不丢未保存草稿，专页返回可回到原列表位置。
5. **批量操作**：先明确选择范围（当前页、筛选结果、全部匹配），预览成功/跳过/失败和影响；批量确认不跳过敏感字段和目标版本检查。
6. **可恢复反馈**：保存、生成、导出、归档和联动都显示进行中、成功、部分成功、失败、结果未知；错误卡提供重试同一操作或回到手动路径，不让 Toast 成为唯一证据。

## 4. 内容与文案规则

| 场景 | 文案结构 | 禁止表达 |
|---|---|---|
| 空状态 | 当前范围 + 为什么为空/未知 + 下一步 | “一切正常”覆盖未读取或未启用范围 |
| 陈旧/部分失败 | 哪部分截至何时可用 + 影响 + 修复动作 | “刷新即可”掩盖权限、缺列或网络原因 |
| 事项状态 | 当前事实 + 证据 + 下一步 + 阻断 | 用“已完成”代替机构受理/用户确认 |
| 字段来源 | 值 + 来源定位 + 形成/核对日 +适用范围 | 只显示链接或“AI 识别” |
| AI 草稿 | 草稿、依据、未知、待确认、应用按钮 | 把模型摘要渲染成正式台账或回执 |
| 删除/归档 | 目标、影响、可恢复时间、关联项 | “删除”含义不清，或把归档说成销毁 |
| 共享/交接 | 接收范围、版本、有效期、撤回方式 | 界面遮盖等同于权限隔离 |

文案优先回答“这对我现在有什么影响”。模块名称和字段名作为辅助，不让用户先理解内部 schema 才能完成事项。金额、日期、单位、成员和来源必须在同一上下文展示，避免只给一个孤立数字。

## 5. AI 在页面中的入口

- 总览卡提供“解释这条提醒”“找依据”“准备下一步”任务菜单，并显示将使用的成员、模块、来源片段和模型服务。
- 事项详情提供“整理材料”“比较新旧凭证”“生成交接草稿”，生成结果进入草稿区，不直接改状态。
- 资料详情提供“基于这段原文提取字段”与“找受影响记录”，仅使用当前选定范围。
- 收件箱提供“按模块分类”“识别缺字段”“查重候选”，用户先确认对象和字段，再进入差异预览。
- AI 不成为顶层导航唯一入口；关闭 AI 后上述页面仍可手工完成核心查看、录入、提醒和导出。

## 6. 移动端与小屏

移动端首层只保留“总览、提醒、收件箱、更多”，台账/成员/事项通过上下文入口进入；底部导航和桌面 Tab 不强行一比一。单手操作时主要按钮位于底部安全区，详情使用全屏页而非 440px 抽屉。长字段、附件、来源和差异以分段折叠展示；离线或后台不可用时显示最近成功时间和手动刷新入口。

## 7. 设计与验收边界

新增页面只有在对应真实任务跨会话、涉及多个来源或需要恢复时才成立。没有这些证据的功能继续留在现有详情/抽屉中。页面设计完成后应留下：信息架构图、状态矩阵、文案表、键盘/触屏路径、移动端降级、合成数据截图和真实思源回归结果。本文的页面均为候选，不代表当前版本已有实现。

## 9. 模块能力矩阵：把“有 schema”与“能工作”分开

当前代码存在三个不同层次：`schemaCatalog` 是字段目录，`provisionModule` 是建库/建列能力，`refreshHub()` 的 provider 才决定是否参与扫描和提醒。模块开关还叠加了用户是否启用、库引用是否存在、权限是否足够和 AI 任务是否可用。它们不能由一个“已启用”布尔值代替。

建议模块卡和设置页统一显示以下状态列：

| 状态列 | 含义 | 未就绪时的界面行为 |
|---|---|---|
| Schema | 字段、枚举、单位和版本是否有目录 | 可查看规划说明，但不能暗示可录入 |
| Provision | 目标数据库/列是否已创建且版本匹配 | 提供预览、创建、局部修复和错误详情 |
| Provider | 是否有真实读取/扫描 provider | 不显示“已扫描”、不把空结果当无数据 |
| Reminder | 是否有确定性规则、运行态和投递回执 | 只显示资料状态或“提醒未覆盖”，不创建伪提醒 |
| AI | 是否有已验证输入、模板和人工替代 | AI 入口置灰并说明原因，核心手工路径保留 |
| Evidence | 结果能否回到原文/附件/回执 | 无证据时标未知或待核对，不生成强结论 |

模块卡最少呈现“当前状态 + 影响 + 下一动作”。例如模块已建库但无 provider 时，应显示“库已存在，提醒扫描尚未接入；可手工查看台账”，而不是“本月 0 条提醒”。模块 ready 的晋级与回退沿用 OR14：schema、读写、提醒、错误恢复、手工替代和对应 AI 模板均通过后才可标 ready；停用模块保留已存数据并明确不会继续扫描。

## 10. 下一批页面候选（PX50–PX60）与升格条件

以下候选用于继续调研宽度，先作为二级入口或设置内页面，不直接扩充顶层导航。只有跨会话、跨来源或需要恢复的真实路径达到 OR16 决策门，才转为 PP 主项：

| ID | 候选页面/入口 | 解决的问题 | 进入条件与边界 |
|---|---|---|---|
| PX50 | 今日处理视图 | 从总览快速处理今日、逾期、待确认和计划事项 | 复用提醒/事项状态；完成后移出且可撤销，不复制规则 |
