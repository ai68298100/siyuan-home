# 开发、交付与验收说明

> 本文说明当前仓库的真实构建与运行方式、主要代码边界和已知限制。页面/功能“已实现”以生产源码与测试路径为准；原型、研究文档和路线图不等同于已交付能力。

## 1. 项目结构

| 路径 | 职责 |
|---|---|
| `src/index.ts` | 思源前端插件入口、菜单/顶栏/状态栏/生命周期、面板挂载及生态事件桥接 |
| `src/kernel.ts` | 思源内核插件入口；当前仅处理生命周期日志，不承担常驻扫描或后台任务 |
| `src/panels/` | Svelte 面板、设置、首次引导、快速录入、头像设置和错误边界 |
| `src/panels/screens/` | 总览、提醒、台账、成员、日历等屏幕 |
| `src/core/` | 领域模型与逻辑：设置迁移、思源 API、schema、成员、提醒、活动记录投影、导入导出、车辆、附件等 |
| `src/bridge/` | 对其他插件公开的 `window.LvHome` 服务桥 |
| `src/libs/`、`src/ui/` | 思源组件适配、对话框、表单、图标和通用面板组件 |
| `src/styles/design-system.scss`、`src/index.scss` | 插件设计令牌、组件样式与主题/响应式样式 |
| `public/i18n/` | 中英文界面词条；构建时生成发布包中的 `i18n/*.json` |
| `plugin.json` | 思源插件清单、版本、最低思源版本、平台、说明和图标配置 |
| `prototype/v6.html`、`prototype/v6.css` | 独立交互设计原型；含演示数据，不连接生产业务数据或思源 API |
| `docs/design/` | 页面契约、交互/视觉规范、产品决策和扩展设计；规划项会单独标记 |
| `docs/guide/`、`docs/FAQ.md`、`docs/privacy.md` | 中文使用指南、常见问题与隐私边界 |
| `tests/` | Vitest 单元测试、桩和契约测试；`tests/live/` 需要真实思源实例单独运行 |
| `scripts/` | 元数据/i18n检查、构建后检查、集成测试及 UI 走查脚本 |
| `dist/`、`package.zip` | 本地构建产物，不是源代码；由构建脚本生成 |

### 页面与组件状态约定

| 模式 | 当前约定 |
|---|---|
| 输入 | 字段附近展示校验信息；提交路径应禁用重复触发并显示处理中状态 |
| 读数据 | 有数据时显示真实记录；空结果应有说明和下一步；请求错误通过可读消息或错误边界提示 |
| 活动记录流 | 显示录入时间/事项日期口径，支持搜索、模块筛选、收起、分页、刷新与来源定位；首次加载、全量失败、空结果、无匹配、部分失败和失联流水分别说明 |
| 写数据 | 成功后刷新相关界面或显示确认；失败时保留可恢复输入并说明原因 |
| 高影响操作 | 删除、清空、覆盖等通过确认对话框告知对象和影响 |
| 键盘/触屏 | 使用语义化控件、可访问名称和可见焦点；触屏主要命中区按移动布局扩大 |
| 禁用/加载 | 禁用态应说明条件；加载态锁定重复写操作。具体控制项的行为契约仍以页面实现及回归记录为准，不应从本表推断未验证功能已经覆盖所有异步状态 |

## 2. 从零开始运行

### 要求

- Node.js `>=24`。
- pnpm `12.9.1`（遵循根目录 `package.json` 的 `packageManager` 声明）。
- 运行插件需思源笔记 `3.8.0` 或更高版本；实际 API 行为还受安装的思源版本和平台影响。
- 本地 UI 走查需可运行 Chromium/Playwright；写型 E2E 需单独的思源隔离工作区。

### 安装依赖、开发和构建

```bash
pnpm install
pnpm run dev
```

`dev` 同时启动前端 app 与 kernel 两个 Vite watch 构建。若要让插件出现在本机思源中，按 [贡献指南](../../CONTRIBUTING.md) 配置 `make-link`，或将 `dist/` 安装/部署到正确工作区；随后在思源中启用插件。请勿将写型自动化测试指向含真实笔记的工作区。

```bash
pnpm run check
pnpm test
pnpm run build
pnpm run smoke
```

建议开发者第一次启动后，先跑类型/Svelte/i18n/元数据检查和单元测试，再进行隔离内核的 UI / API 实测。测试详见 [UI 走查手册](../testing/ui-walkthrough-runbook.md)、[设备批处理手册](../testing/device-batch-runbook.md) 与 [贡献指南](../../CONTRIBUTING.md)。

## 3. 环境变量

插件运行时不需要用户配置自有服务 URL、账号、密码或 API 密钥。下列变量仅供构建工具和本地测试脚本使用；未列入本表的机器路径不要照搬到其他开发环境。

| 变量 | 用途 | 默认/注意事项 |
|---|---|---|
| `NODE_ENV` | Vite 开发/生产构建模式 | package scripts 设置；一般无需手动传 |
| `VITE_BUILD_TARGET` | 构建 `app` 或 `kernel` 入口 | 未设时默认为 `app`；`kernel` 由开发/构建脚本传入 |
| `VITE_SOURCEMAP` | `inline` 时启用内联 source map | 仅开发脚本启用，生产构建关闭 |
| `SIYUAN_BASE_URL`、`SIYUAN_URL` | live/e2e 脚本使用的思源内核地址 | 默认 `http://127.0.0.1:6806`；具体脚本的优先级见脚本说明 |
| `SIYUAN_TOKEN` | 向测试内核发送 API 鉴权令牌 | 从隔离测试实例获取；不要提交到仓库、日志或截图 |
| `TEST_WS_TOKEN` | 设备批量 E2E 的兼容令牌变量 | `SIYUAN_TOKEN` 优先；仅特定脚本读取 |
| `TEST_WS_URL`、`TEST_WS_PORT`、`TEST_WS_DIR` | UI 走查靶场地址、端口、工作区路径 | 默认 `127.0.0.1:14680` 与仓库下 `tmp/sy-ui3`；建议覆盖到独立临时工作区 |
| `SIYUAN_KERNEL` | UI 走查启动内核可执行文件路径 | 脚本当前有 Windows 默认值；非该路径环境请显式配置 |
| `TEST_WS_AUTH_CODE` | UI 浏览器登录用靶场访问码 | 默认走查脚本值只适用于新建测试靶场；勿在真实工作区复用 |
| `SIYUAN_E2E_ALLOW_SHARED` | 显式豁免写型 e2e 的隔离工作区守卫 | 默认不豁免；设为 `1` 有误改真实数据风险，不建议设置 |
| `SIYUAN_E2E_AI` | 开启可能调用已配置模型服务的 e2e 测试 | 默认关闭；设为 `1` 前需确认测试会向所选 AI 服务发送数据 |
| `SIYUAN_TARGET_DIR` | `make-install` 的插件目录目标 | 不设置时尝试探测并交互选择 |
| `SIYUAN_PLUGIN_DIR` | `make-link` 无法自动探测时提供插件父目录 | 目标是工作区的 `data/plugins/` |
| `SMOKE_EXTRACT` | 强制选择发布包解压工具 | 可用 `unzip`、`powershell` 或 `python`；默认自动尝试 |

变量名和默认值来自当前 `package.json`、`vite.config.ts` 与 `scripts/`；不同 e2e 命令接受的参数并不完全相同，遇到歧义请以该脚本源码为准。

## 5. 数据、API 与鉴权边界

- 业务数据以思源数据库、块与资源附件保存；插件自己的 storage 用于用户设置、成员配置和提醒运行态等，不是业务台账的第二份主库。
- 前端通过 `src/core/siyuan.ts` 收口访问思源提供的同源内核 API；一般请求使用思源 SDK 的 `fetchSyncPost`。上传资源走同源 `/api/asset/upload`。
- 插件没有独立登录页、用户 token 生命周期或角色权限系统。请求沿用当前思源会话/宿主授权；权限不足和锁屏行为取决于思源实例、部署方式和登录状态。
- 请求层按读取/写入统一处理去重、竞态淘汰、15 秒超时、调用方取消、读取限次重试、本地操作 key 与负载指纹校验。操作 key 只保证本机重复点击合并和结果识别，不代表思源内核已经提供服务端幂等；更新同一值的写入可限次重放，建笔记本、建文档、插块、加列、建行和上传等创建类写入永不自动重放。
- 写入不是完整事务系统：响应超时、网络中断或取消后服务端提交状态可能未知。创建类操作会先回读并仅在唯一匹配时恢复；仍无法确认时保留“结果待确认”状态，用户必须核对真实台账/资源后再决定是否重试，不能盲目新建。
- plugin storage 和思源台账的备份、同步、协作、访问控制由思源提供。插件无逐用户 ACL 或字段级加密。
- 完整证件号码可以被保存；UI 掩码只是显示层处理。号码可能出现在思源台账和用户主动导出的 CSV 中；诊断包不包含证件号码。

## 6. 构建与部署

### 本地构建

```bash
pnpm run check
pnpm test
pnpm run build
pnpm run smoke
```

`pnpm run build` 输出 `dist/` 和根目录 `package.zip`。包内包含运行所需的 `index.js`、`index.css`、`kernel.js`、`plugin.json`、中英文 i18n、README、图标/预览和许可证；`docs/`、`prototype/`、`tests/`、`scripts/` 等开发资料不应进入插件包。前端按当前 Vite 配置保持单文件打包，不能擅自开启代码分割，否则思源加载器可能无法解析相对 chunk。

### 安装到本机思源

- 开发热更新：运行 `pnpm run dev` 后，用 `pnpm run make-link` 建立链接。Windows 若普通命令权限不足，可按项目现有 `make-link-win` 说明操作。
- 复制部署：运行 `pnpm run make-install`，脚本把 `dist/` 拷贝到所选插件目录。
- 手工验收安装包：使用思源“设置 → 集市 → 下载”的导入入口选择 `package.zip`，启用插件并检查启动、建库、读写和卸载重开。

写型自动化验证需部署到隔离 workspace。不要在含真实笔记或同步数据的工作区运行会建库、删库、导入或批量造数据的脚本。

### GitHub 发布

发布前按 `docs/release-checklist.md`、`CONTRIBUTING.md` 检查版本、变更说明、双语 README、元数据、检查/测试、构建包和 smoke test。发布工作流与 GitHub Release/集市提交是不同流程；本说明不代表当前存在未发布待办，也不替代维护者对外发布决策。实际 workflow 以 `.github/workflows/` 当前文件为准。

## 7. 验收状态与尚未完成事项

### 当前可确认的实现边界

- 生产代码包含总览、提醒、台账、成员、日历和设置相关界面及对应模块逻辑；31 个模块 schema 目录由 `src/core/schema.ts` 维护。schema 存在不等于每个模块都完成完整的独立详情、跨模块时间线或移动端实机验证。
- 总览和成员卡使用共用的 `ActivityFeed` 读取真实台账/流水投影；能否显示记录取决于模块已启用、schema 声明活动日期或存在对应流水、日期有效、成员关系可解析及思源读取权限。活动快照只保存在进程内并按模块读取结果标记覆盖；没有显式活动日期、录入时间或有效流水日期的记录不会被虚构成近期活动。
- 台账活动时间优先取思源行返回的真实录入时间，缺失时回退到 schema 指定的事项日期；rowlog 活动优先使用流水条目的真实录入时间，并保留事项日期供辨认，缺失录入时间时按事项日期排序。成员活动只纳入明确关联到该成员的台账行及其流水，不根据标题推断关系。
- ActivityFeed 支持按名称/模块/成员/摘要字段搜索、模块筛选、折叠、分页和手动刷新；点击记录打开对应台账记录或流水详情。首次加载显示读取进度；全量失败可重试；空结果与筛选无匹配分开说明；部分模块失败会保留可读结果并提示范围可能不完整。孤立 rowlog 不会被静默删改，会计入提示。
- 车辆领域已有车辆档案与加油、充电、维护记录等生产代码；统计结果取决于用户录入的连续里程/金额等有效数据，混动场景部分单位指标会明确显示不适用。
- 证件可录完整号码，默认遮挡显示；身份证格式/校验与掩码逻辑见 `src/core/idcard.ts`，台账交互见 `src/panels/screens/ledger.svelte`。
- 请求层并发去重、只读重试/超时及写请求不自动重试有单元测试覆盖；这不能证明所有页面操作都具备完整的五态或可回滚事务。
- UI 原型 `prototype/v6.html` 使用合成数据独立运行，可用于布局/交互讨论，但不是生产页面或真实数据服务，也尚未被证明与所有生产控件状态完全一致。生产页面契约中的“已实现/部分实现/规划”以 `docs/design/04-交互与UI原型.md` 的标注为准。

### 自动化与人工验收门

### 已知限制 / 未来工作

1. 当前宿主 SDK 的 `fetchSyncPost` 类型没有公开服务端幂等语义；插件传递的操作 key 仅作关联信息和本地去重。读取超时会停止向页面交付结果；底层传输是否真正中止取决于宿主实现。创建类写请求若发生网络中断，服务端提交状态可能未知，插件会尝试回读唯一结果，无法确认时必须由用户核对后再操作。
2. 插件沿用思源宿主会话；鉴权失效会发出统一事件并保存返回位置，由宿主登录页完成重新认证。逐用户 ACL 或字段级加密仍由思源管理。
3. Android WebView 软键盘、系统返回键、旋转、安全区，独立窗口、兄弟插件并发及跨端冲突需要真实设备/实例回归；Chromium 自动化不能代替这些验证。
4. 活动记录流已能读取明确声明活动日期的启用模块和可关联的 rowlogs，但不是覆盖所有模块/所有历史的完整全局索引；没有活动日期定义、有效日期或成员关联的源记录不会显示。成员时间线当前仅是关联台账记录与流水，并不聚合提醒/事项/附件。全局跨模块搜索与生产提醒时间线仍为部分实现或规划，不应按原型稿当作生产能力宣传。
5. `prototype/v6.html` 仍有演示数据/独立交互；原型与实现的双向逐控件状态镜像和完整组件状态图尚未形成单一自动化验收链。
6. 超长清单的虚拟滚动、代码拆分和媒体/字体优化必须先有可复测的性能基线再作取舍；当前构建配置出于思源加载器限制将前端打成单文件，不应仅为常见 Web SPA 优化直接拆 chunk。

本轮仍未闭环项：补测压力走查耗时。此前 `ui:media` 首次运行的 `print-dark` 断言失败已通过第二次复跑确认修复/通过。新增验证结果、未通过项和修复记录应更新本节或关联的验收文档，并注明验证环境；不要只改“通过”字样而不留命令或证据。
